**r2**（`first-set-2026-11-01-r2`・2,996,422 B・sha256 `71c9ce0b…`・書体パック 1 個 release 1.1.0）の記録は、
タグ `first-set-2026-11-01-r2`（`8329524`）の `release/first-set.json` に残っています
（`git show first-set-2026-11-01-r2:release/first-set.json`）。

説明書き（Release の本文）は `first-set-notes.md` です。`.github/workflows/release-set.yml` が、この記録の大きさと sha256 を
足して Release を**作り**（すでにあれば添付だけ）、CI が作り直した ZIP を添付します。`check-docs` が説明書きの有無も見ます。
r2・r3・r4・r5 はこのやり方で公開済みです（r4 からは `.zip` と `.stlib` の 2 つを添付します）。
r5 からは、添付の前に **`tools/verify-set.mjs`** で「trk235 が開いて中身を入れられる形か」を確かめます。

## なぜ 5 つあるか

- **r1 → r2**：書体パックに `licenseFile`（ライセンス全文の宣言・L7）を足したため、パックの release を **1.0.0 → 1.1.0** に上げました
- **r2 → r3**：書体パックを 14 種足したため（**1 → 15 パック**）、目録が変わり、目録を同梱しているセットも作り直しになりました。
  相手側（trk-PWA）と相談して、**版を上げる方式（A）** に決めたので、r3 として新しく配っています
- **r3 → r4**：**`gallery/fonts.html`（書体の一覧と検索・L13／L14）** と **`set.json`**（セットの名前と版・trk235 の任意ファイル）が
  中身に増えたため。目録にも `fonts[].tags` と `fonts[].bytes` が入りました。あわせて **`.stlib` でも配る**ようになりました
  （`.zip` と**同じバイト列**・sha256 も同じ。trk235 以降は `.stlib` をそのまま選ぶだけ）
- **r4 → r5**：`README-はじめに.txt` に「**アプリが読むのは `catalog/index.json` と `packs[].file` だけ**（`gallery/` と `set.json` は
  読まなくても動く）」と、**trk235 以降の入口（📦 セットを選ぶ）**を足したため。パックの中身は r4 と同じです

- **配ったタグは作り直しません**（配ったものを差し替えると、落とした人の `sha256` と合わなくなるため）
  - ただし、**まだ何も公開されていないタグ**なら指し直してかまいません（r2 の最初の push は、CI が Release を作れずに
    失敗し、アセットは 1 つも配られていませんでした。そこで `release-set.yml` を直したうえで、タグを `8329524` に付け直しました）
- 同じ日にもう一度配るときは、`sets/first-set.json` に `"rev": "r5"` のように書きます（ファイル名とタグの後ろに付きます）
- **過去の記録は、そのときのコミットで再現できます**：
  `git worktree add /tmp/r1 first-set-2026-11-01` → `node tools/build-set.mjs sets/first-set.json`
  （タグ `first-set-2026-11-01` は `0801508`。当時のパック 1.0.0 が入っています）

## 古いパックを持っている人へ

新しい `.stpack` を選ぶと入れ替わり、`licenseFile` も一緒に入ります。
