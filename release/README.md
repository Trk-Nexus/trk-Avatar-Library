# release/ — 配ったセットの記録

**はじめてセット**（見本 HTML＋目録＋書体パック 1 つ）の、配ったときの記録です。
ファイル名・大きさ・sha256・中身の sha256 が入っていて、`node tools/build-set.mjs sets/first-set.json --check`
（CI でも実行）で、いまの倉庫から作り直したものと一致するかを確かめます。

| 記録 | タグ（Release） | 大きさ | sha256 | 中身 |
| --- | --- | --- | --- | --- |
| `first-set-2026-11-01.json`（過去） | `first-set-2026-11-01` | 2,993,307 B | `b9599930c9e5…` | 見本 51,711 B・目録 2,795 B・書体パック **1.0.0**（2,935,978 B） |
| `first-set.json`（いま） | `first-set-2026-11-01-r2` | 2,996,422 B | `71c9ce0bbd07…` | 見本 54,318 B（「🔤 同梱の書体」の節つき）・目録 2,879 B・書体パック **1.1.0**（2,936,399 B・`licenseFile`） |

説明書き（Release の本文）は `first-set-notes.md` です。`.github/workflows/release-set.yml` が、この記録の大きさと sha256 を
足して Release を**作り**（すでにあれば添付だけ）、CI が作り直した ZIP を添付します。`check-docs` が説明書きの有無も見ます。

## なぜ 2 つあるか

書体パックに `licenseFile`（ライセンス全文の宣言・L7）を足したため、パックの release を **1.0.0 → 1.1.0** に上げました。
そのため、はじめてセットの中身も変わっています。

- **同じタグを作り直していません**（配ったものを差し替えると、落とした人の `sha256` と合わなくなるため）
- 同じ日にもう一度配るときは、`sets/first-set.json` に `"rev": "r2"` を書きます（ファイル名とタグの後ろに付きます）
- **過去の記録は、そのときのコミットで再現できます**：
  `git worktree add /tmp/r1 first-set-2026-11-01` → `node tools/build-set.mjs sets/first-set.json`
  （タグ `first-set-2026-11-01` は `0801508`。当時のパック 1.0.0 が入っています）

## 古いパックを持っている人へ

アプリ（trk231 以降）の目録の一覧に **「更新あり（1.0.0 → 1.1.0）」** が出ます。
新しい `.stpack` を選ぶと入れ替わり、`licenseFile` も一緒に入ります。
