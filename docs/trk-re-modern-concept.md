# trk-re-modern コンセプト・制作方式・紹介書式

版 1.1 ／ 2026-11-07（制作メモと公開向けの読み物を分ける方針を追記）

## はじめに

**trk-re-modern は、スキンの色や形を変えるだけでなく、その作品や言葉の持つ意味を、書体・色・余白・動き・操作を通して体験にするための作品カテゴリーです。**

「なぜこの書体か」「どのような場所で、どう感じ、どう使ってほしいか」「何を優先し、何を選ばなかったか」を説明できることを目指します。見た目と使い心地を一緒に設計し、使用者が作品の理由・出典・制約をたどり、必要に応じて選び直せるようにします。

本書はカテゴリー全体の考え方と使用方式を定めるものです。個々の作品の完成・公開、PWA側の新機能の実装や合意を意味しません。制作時は必ず [制作・調査・公開ガイドライン](trk-re-modern-guidelines.md) に従い、紹介には [個別作品紹介・カタログ書式](trk-re-modern-introduction-template.md) を使います。基準は作品ごとに実際の根拠と検証を記録することであり、機械検査だけで品質や安全を証明するものではありません。

## 1. 作品としての考え方

### 1.1 言葉や概念から、体験へ

作品名や着想を飾りにせず、その概念が色の役割、書体の性格、素材や余白、演出の有無、画面の使い方にどう結びつくかを考えます。例えば「静けさ」を選んだから暗い色にする、と短絡するのではなく、読書・情報確認・再生といった場面で、何を目立たせ何を落ち着かせるのかを説明します。

書体が持つ文化的・歴史的背景については、作者や一次資料の説明を確認し、作品の創作意図と史実を区別します。見た目がレトロであることと、特定の機種や時代を忠実に再現することは同じではありません。作者の公認や資料の内容を推測しません。

### 1.2 意図の違いを認める

- **美学**：色、素材、光、透明感、書体、世界観。
- **機能**：読みやすさ、集中、情報の階層、操作、場面に応じた快適さ。
- **実験**：明確な目的と制限を持つ新しい表現や技術。

作品はこれらを組み合わせられます。全作品を同じ見た目や単一の尺度に揃えるのではなく、それぞれの意図と代償を明示します。ただし表現の自由は、警告・選択・設定・解除を読めなくしたり、危険な演出や権利不明の素材を許したりする理由にはなりません。

### 1.3 説明できる、変更できる

完成時の紹介だけでなく、調査した資料、作者・ライセンス、選択の理由、実装された範囲、検査と残課題、更新理由を残します。将来の修正で「意図を保った変更か」「誰の設定に影響するか」「再検証は何か」を追跡できるようにします。未確認・提案・候補・実装・検証済みを混同しません。

### 1.4 作品を見て、背景を読む：読み物と制作メモ

**2026-11-07 の依頼者の方針：開発メモは未整理のままでも残し、公開向けの読み物とは分ける。** どのような概念・歴史的文脈・図柄・書体を調べ、何を選び、何を選ばなかったかを、後からたどれるようにします。資料の説明、制作側の解釈、未確認の仮説は区別します。

- **制作メモ**は、制作中の問い、調査先、観察、候補、判断の変化や保留を、整った文章を待たずに残す場所。後から根拠と決定過程を振り返れます。未確認のものを決定や事実として扱わず、必要に応じ追記・訂正します。
- **公開向けの読み物**は、その作品の概念と選択理由を読者に伝える文章。制作メモをそのまま公開するのではなく、出典・権利・事実・現在の実装状態を確認し、読みやすく編集します。公開できる参考資料や確認済みの記録に辿れるようにします。
- 「裏面」は見本に添える読み物の**体験上の呼び方**です。具体的な切替UI・構図・動きの採用は別途検討し、PWAの実装や公開済み機能と混同しません。見本の案を実際に選べるかどうかも明示します。

作品紹介と制作記録の扱い、公開時の注意は[紹介書式](trk-re-modern-introduction-template.md)に整理します。研究用の[ピクセル・コンソール文章見本](re-modern-research/05-concept-reverse-pixel-console-draft.md)は説明例であり、完成済みの公開ページではありません。

### 1.5 自由な発想と、利用者が選べる拡張

2026-11-07 の依頼者の方向性として、Avatar Library の制作は PWA の現在のオフライン完結や既存機能だけに発想を縛らず、メディア・用途特化・芸術・自由な構成や、必要に応じた別実行環境・拡張機能も責任を持って研究します。一方、作品の紹介を参照することと、追加機能や通信・権限を利用することは別とし、導入は利用者が選べる形を目指します。

これは PWA の既定動作を変更する決定や、利用者・OS からの権限付与、外部ソフト・API・ローカルサーバーの導入を意味しません。利用者の許可・停止と既存設定の保護、権利・安全・互換の検討は省略しません。目的別の受け口や別実行環境を作る場合は PWA 側と別途協議し、[拡張機能の検討記録](re-modern-research/06-creative-freedom-and-capabilities.md)と[制作ガイド](trk-re-modern-guidelines.md)に従います。

## 2. 体験を設計する方式

### 2.1 色・面・文字・演出を役割で決める

各作品で、背景、パネル、本文、補足、境界、フォーカス、状態、選択色の役割と理由を決めます。透明・半透明や映像との重なりがある場合は、実際に重ねた後の条件も検証します。色だけで意味や状態を区別せず、文字・形など別の手がかりを検討します。

動きは作品の目的に照らして選び、停止・軽減・静止への代替を考えます。点滅の危険や背景動画・共通エフェクトを無視しません。画面の美しさと、文字拡大・強制色・キーボード・読み上げ・タッチなどの利用を対立するものとせず、両方の評価を計画します。個々の具体的な基準と検証はガイドラインに従います。

### 2.2 書体を「理由と出典のある素材」として扱う

見出し、本文、数字やラベル、読書、ゲーム表示など、用途ごとの役割を決めます。**見本で実際に使用した書体、作品で実際に使用する書体、検討中の候補は別に表示します。**

正式名・作者・太さ・入手元・版・実ファイル・ハッシュ・容量・ライセンス・表示や再配布の条件を確認します。アプリ内部の family 名と元の書体名を混同しません。端末の `system-ui` は実際の書体が端末や文字によって異なり、書体名が指定されていてもロード済みとは限りません。欠字、言語、未導入、読み込み失敗時の代替と、使用・解除時の影響を記録します。

**作品の基本表示には、概念に合い、実際のファイルを必要な条件で頒布・利用できる書体を原則として一つ以上用意する**方向です。対象の画面・文字に必要な字種、容量、供給・読み込み・解除を確認し、配布物を導入しただけで意図した基本表示が得られる経路を検証します。利用者が選んだ既存設定は尊重し、欠字・読み込み失敗時には読める代替を用意します。「書体名がある」「同梱した」だけで実際に画面に適用される保証とはしません。

再配布できないが利用者自身が正規に入手・利用できる書体も、作品の**任意の別案**として考えられます。同梱せず、条件を確認できた範囲で文字見本画像や出典、入手方法を紹介し、使うかどうかは利用者が選びます。画像の作成・公開・再配布にも書体や画像自体の条件があり、利用者の使用許可だけから許されると決めつけません。文字見本は実際に使える機能ではなく、説明の代わりに文字を画像化しません。

紹介から既存の書体一覧や資料へ辿れることを目指しますが、資料へのリンクは再配布の許諾でも、書体の自動適用機能でもありません。外部資料を開くこと、素材を取得すること、スキンに適用することは分けて説明します。個別の供給や PWA への適用方法は別途合意し、勝手な取得・通信・設定変更を行いません。

### 2.3 同じ概念を、異なる場所に合わせる

共通UI、書斎、基地、ゲームなどに同じ作品の世界観を展開する場合でも、場所の目的に合わせて表現を調整します。

| 領域 | 守るべき体験の例 |
|---|---|
| 共通UI | 操作、警告、スキンの選択、設定、解除 |
| 書斎 | 本文の読みやすさ、利用者の本文テーマ・文字設定、編集・検索・しおり |
| 基地 | 再生状態、操作、字幕、映像・ジャケット、画中画、退出 |
| ゲーム | 情報の識別、ノーツや設定、譜面・背景、プレイ中の安全性 |

書斎や基地の領域別スキン・連動・独立選択は**PWA側との検討が必要な提案**です。現時点で対応済みとはしません。現状維持を出発点とし、選択・影響範囲・保存・復元・旧版・失敗時の代替を受け手と合意します。利用者の既存の読書設定や共通ノーツを、作品を選んだだけで勝手に上書きしません。共通色が既に一部に適用される箇所もあるため、「現状維持」は現行動作を保つ意味です。

## 3. 制作から公開までの流れ

1. **問いと意図**：作品が表現する概念、使う場面、対象領域、優先事項・トレードオフを整理する。
2. **調査**：Modern Web Guidance の該当箇所を版を固定して確認し、必要な一次資料、作者、書体、素材、権利、検索語・日付を記録する。公開資料の検索・制作時のブラウザ検証は環境の範囲内で可能だが、実行時の権限、外部送信、素材の再配布、公開の許可とは別。
3. **仮案と見本**：色・書体・透明・形・動き・画面ごとの案を作る。見本は実PWAと異なる場合を明示し、未実装の切替・操作を動くものとして見せない。
4. **実現方式の確認**：既存PWAの受け口と仕様を調べる。新たな領域・データ形式・書体の供給・設定の優先順位や復元が必要なら、PWA側と合意してから実装する。
5. **検証とレビュー**：機械検査、対象ブラウザ、表示・操作・安全な解除、権利、多言語・欠字、失敗時を確認する。実機や当事者を含む人による確認、別の人のレビューを計画し、未実施や失敗を残す。機械検査の成功を人手レビューやWCAG適合の証明にしない。
6. **登録と公開**：ガイドラインに沿い、別 ID・タグ・台帳・作品記録・レビュー・公開詳細・検索導線・検査を揃える。条件を満たさない案は作業案として保留する。既存作品を無断で上書きしない。
7. **更新**：変更理由、対象範囲、旧版・保存設定への影響、再検証、未解決事項を履歴に残し、関連する作品ページとカタログを更新する。

## 4. カタログと個別紹介の方式

一覧は作品を探すための入口、個別ページは理由と利用条件を読む場所です。同一の見出しを使いながら作品固有の内容を説明し、比較や後の修正を容易にします。詳細は [紹介書式](trk-re-modern-introduction-template.md) を参照。

- 一覧：作品名・状態・一文の概念・元作品・対象領域と実装状況・実使用書体と候補書体・詳細への導線。
- 詳細：概念と選択理由、領域別の設計、色・透明・演出、書体の正式情報、出典と権利、利用条件・戻し方、検査、未検証、変更履歴。
- 検索：作品名・概念・領域・書体などから到達できること。候補が検索に出る場合は候補と明示する。検索語の外部送信や追跡を前提とせず、JavaScript無効時も一覧と詳細を読めるようにする。
- 修正：どの作品・領域・書体に影響する変更かを記録し、作品詳細と一覧の情報を矛盾させない。公開後はリンク・権利情報・実際の配布物との整合も確認する。

現行の作品JSONの `typography` は１組の構造欄です。複数の書体や領域別の状態は人が読める詳細・検証記録で区別します。構造を拡張する際は、互換性・移行・機械検査・公開パイプラインを合わせて設計します。構造検査は記載の真偽やレビューの実在を証明しません。

## 5. 最初の研究例：ピクセル・コンソール

`pixel-8bit` を出発点に、**「ドットの秩序は残し、読むための文字は犠牲にしない」**という方向を検討しています。静かな暗色面、限られたアクセント、角形のリズムを提案し、歴史的な8ビット機の忠実な復刻とは言いません。

制作データと初期見本は端末の system 系書体を使い、DotGothic16 Regular 400 は見出しの**候補**です。[隔離した書体研究見本](re-modern-research/12-font-included-isolated-study-2026-11-07.md)では、この候補の実ファイルを任意にロードする試験を始めていますが、PWA 作品への導入・適用は未実装です。既存パックの出典の一部は訂正済みで、配布 NOTICE と既存 pack の旧上流リンクはまだ未修正です。404 は直ちにライセンス違反を意味しません。PWAで見出しに限定して供給する方法、字種、復元も未解決です。

書斎と基地への展開は構想段階。PWAには利用者が明示的に使う「スキンのおすすめ」ノーツ設定がありますが、共通ノーツに保存され、スキンを変えても自動的に元には戻りません。実環境・利用者による検証と安全な案内が必要です。
