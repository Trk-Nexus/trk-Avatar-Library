対象：[PWA 側の質問](https://drive.google.com/file/d/1ZjRo_u7Idd_MQf-ocINIAGd1_RofUIap/view)／[PWA trk309 を含む main 固定版 `3298de779083f478105d7694e871bf7e80119a5a`](https://github.com/Trk-Nexus/trk-PWA/tree/3298de779083f478105d7694e871bf7e80119a5a)。以下は Avatar 側からの提案で、PWA 側との合意や実装完了を意味しません。

## 結論

依頼者の決定どおり、**未確認作品の色は既定で当てない**ことを前提にします。開発のための例外は、利用者に気付かれない一般設定やリンクに混ぜず、意図をもって選んだ検証に限ります。

### Q1. 置き場所

- **現段階は (c) 手順書＋既存の開発者 API を、隔離されたテスト用プロフィールで使う**ことを提案します。まだ見た目が題字に限られ、画面や安全な解除の設計を確認中のためです。コンソールの存在をアクセス制御・セキュリティ境界とはみなしません。通常利用の案内には載せません。
- 将来、複数の作品・領域の評価で人が頻繁に使うようになったら、**(a) 専用の開発・検証画面**へ移す案がよいと考えます。目的と影響を説明し、明示操作でオン、いつでもオフ、状態と対象を見えるようにします。単に隠しただけでは安全対策にはなりません。機能の要否・公開範囲は PWA 側と別途決めたいです。
- **(b) URL だけで自動的にオンにする案は採らない**ことを推奨します。URL は共有・履歴・再読込等で意図せず持ち運ばれうるためです。URL で検証画面を開く場合も、リンクを開くだけで有効にせず明示的な操作を求めます。
- オンは可能なら**検証セッションに限定**し、終了時にはオフ、設定の書き出し・インポートやバックアップ復元で一般利用環境へ持ち越さない設計を提案します。セッションの範囲、再読込・複数タブ・クラッシュ後の挙動は別途決めて検証してください。現行 trk309 は `settings.remodernDevPaint` を保存し、**再読込後もオンが残る**ため、これは将来の要望であって現行動作ではありません。
- 明示的なオフ時には再描画して未確認色を外し、他の作品・ノーツ・読書・再生設定を触らないこと。保存失敗時は状態を明確に通知し、再読込後の状態も確かめられること。現行 API は `saveUserPrefs()` の戻り値を使わずメモリ上の値を返すので、戻り値だけを保存成功の証明としません。

### Q2. 印

**はい、オンの間は表示を希望します。** 例：「開発用：未確認作品の色を試験中」。ただしオンであっても作品が未選択、対比不足、未実装などのため実際には色が当たらない場合があるので、より正確には「開発用：未確認作品の色の試験が有効」など、**スイッチが有効な状態**と実際に色が適用された状態を区別して表示します。

- 設定画面の一時的な説明だけではなく、影響を受けうる領域を操作中にも分かるよう、検証用の目立つ固定表示や各領域の状態表示を検討。`未確認` を保持し、「正式・安全・検証済み」と誤認させない。
- 色だけに頼らない文言、キーボード操作、読み上げ、狭い画面・拡大・強制色、多言語を考慮。題字や操作・本文・字幕を覆い隠さない。常時表示の具体的な配置は実画面で確認する。
- 分かりやすいオフ操作と適用状態への反映を用意する。現行のコンソール API は画面上にスイッチや常時表示を出しておらず、この提案は未実装です。

### Q3. Avatar 側での使用場面

**あります。** 例えば利用者に作品として承認されたが、正式な台帳登録・公開はまだ行っていない「ピクセル・コンソール」の検証用ファイルを取り込み、未確認で通常は色が当たらないことを先に確かめたうえで、一時的にオンにして共通題字の色・対比・元に戻す操作を評価します。実機・背景・読書画面・基地が実装された後は、それぞれ別に検証します。作品への承認と**台帳登録・配布物の確認**は別です。

テストは隔離した PWA コピー・専用プロフィールで行い、終了時に明示的にオフにして再読込後も確認。公式台帳への仮 ID 追加や、本番の設定を変更して検証を通す方法は使いません。既定オフのテストはオンの試験と分けます。

trk309 の現行 API を検証用プロフィールのブラウザ開発者コンソールから使う場合、読み込み・選択・「適用」の後、状態を `window.TrkReModernDev.isUnverifiedPaint()` で確認し、明示的に `window.TrkReModernDev.setUnverifiedPaint(true)`。確認後に必ず `window.TrkReModernDev.setUnverifiedPaint(false)` を呼び、再読込して `isUnverifiedPaint()` が false のことと題字が戻ったことを確かめます。スイッチは再読込では消えません。保存失敗・API が無い場合は継続せず、その場の状態を確認して検証を中止します。コンソールへの不明なコードの貼り付けはしません。

## 登録簿と信頼の境界

固定 PWA の台帳写しは ID の一致を調べる仕組みで、ZIP のハッシュや作者を認証しません。既存の ID と一致しただけで、持ち込まれた内容が公式の同一ファイル、もしくは安全と保証されたことにはなりません。今は両側の台帳が空です。将来必要なら、公開済み配布物のハッシュをどう正本化・同期・照合するかを別の契約として検討し、ID 一致と配布物確認の表示を分けたいです。
