## 2. 範囲と優先順位：実装できる具体案

現状の `body.trk-title-font-on .brand h1, body.trk-title-font-on #skinGrid .skinCard b` は、ピクセル・コンソールの選択に関係なく共通題字と**全作品の一覧名**を対象にします。ロック表示にも作用し、各カードの `--sk-title` より優先します。`.brand h1` では trk246 の display 指定と同じ詳細度で後にあるため、題字については新指定が勝ちます。作品名の `#skinNow` や詳細画面は対象外です。設定値自体を消すわけではなく、解除すれば以前の CSS が再び効く設計です。

PWA 側が全体設定を提供するなら、次の二層として扱う提案です。

1. **全体設定**：明示的にオンにした人に限り、対象を「共通題字とすべての作品名一覧」と表示する。既存の個別題字／trk246 より優先されることと、一覧以外は変えないことを事前に説明する。元の設定値を保存・上書きしない。オフで元の表示に戻る。
2. **作品連携（別途・任意）**：ピクセル・コンソールが対象である間だけ、共通題字と**対象作品のカード名だけ**に適用する。作品切替・解除時に当該作品由来の指定を取り除く。他作品・本文・既存書体設定は維持する。導入済みの書体データの削除はしない。作品自体は書体未導入でも system 系で成立させる。
3. **両方ある場合**：利用者が明示した全体設定を優先し、全体設定がオフの場合のみ作品連携が効き、どちらもオフ／利用不可なら既存の trk246・作品指定・通常表示へ復帰、という順を推奨します。**実装可能な一案であって、PWA 側の承認済み仕様ではありません。** 既存の他の明示設定とも整合させてください。

例：他作品を選択した状態で作品連携だけオンなら、全体の題字も他カードも変更しない。ピクセル・コンソールへ切替えると対象箇所だけ変化し、離れると復帰。全体設定を別途オンにした場合のみ、説明どおり全カードに適用される。未対応 PWA や未導入時に見た目が安全に戻ることを保証し、作品パック自身が設定を勝手に切り替える仕組みは求めません。

### B. ライセンス表示、モバイル、およびオフライン更新

- 固定版で `node tools/prepare-mobile-web.mjs` を**一時コピー内で**実行すると、`mobile-web/fonts/licenses/` の4全文がいずれも欠けました。ステージング対象は `assets, css, icons, js` と限定 docs で、`fonts/` が含まれないためです。これはステージング成果物の確認であり、Capacitor 実機は未試験です。ネイティブ版でも4件を含め、Dot＋Neo はそれぞれの全文・著作権表示を開けるようにすることを提案します。単にフォント本体を同梱しないことと、配布するライセンス情報を提示することは別です。
- PWA 側も未キャッシュのオフラインでは読めない場合があると記録しています。`sw.js` は同固定版でも trk314 と同一の cache 名で、差分にも含まれず、`index.html` の build 表示も trk314 です。旧インストールに対する service worker の更新、オンラインで殻を更新した後の完全オフライン起動、新旧 HTML・JS・CSS の混在、ライセンス未取得・取得済みの両方を実機で確認してください。shell precache は index の script/link 等を列挙しますが、後から fetch するライセンス全文はその列挙だけでは先読みされません。必要な build/cache 更新と全文の事前キャッシュ、または確実な代替提示を PWA の既存方針に合わせて検討してください。**SW が変わらないと初回 install が自動的に再実行されるとは限りません。**
- ライセンス全文 fetch は、現コードでは成功前に読込済みフラグを立てます。一度失敗すると、同じ描画の開閉だけでは再試行できません。成功時のみ確定し、失敗後の再試行を可能にしてください。作者・対象版・OFL 全文・Reserved Font Name と表示対象を照合し、Press の作者版と Fontsource 版の表示を混同しないでください。これは法的結論ではなく、最終確認が必要という意味です。

### C. 失敗・削除・複数タブ

- 前の Galmuri が適用中でも、未導入の Dot＋Neo に切り替えると、前の拡張は解除され、Dot＋Neo が選択として保存され、通常表示へ戻ります。「今の題字のまま」が**以前の拡張を保持する**意味にも読めるので、画面と仕様を一致させてください。推奨は、次候補の全ファイル検証・ロード成功までは以前の有効な選択を維持し、失敗理由を表示する方式。通常表示へ戻す方式を採るなら明記してください。いずれも部分適用はしません。
- Dot＋Neo の削除はファイルごとに別トランザクションです。2件目の削除失敗を注入すると、1件目だけ消え、選択と画面の active 状態は残ります。1つの IndexedDB トランザクションにまとめるか、失敗時に残存状況を再読取し、適用と選択を安全に整合させてください。別候補や作品も将来参照する共有ファイルは、参照関係を確認してから削除してください。
- 選択中候補の削除後、localStorage の選択消去失敗を注入しても削除結果は成功となり、選択だけ残って missing になります。DB と localStorage は単一トランザクションにできないため、失敗を報告し、再読取・再起動後も説明可能な回復状態にしてください。「削除」「解除」「選択解除」をそれぞれ明確にすることが大切です。
- 2タブで有効な書体を片方で削除すると、もう片方は自発的に再読取するまで適用を保持します。保存先名は origin 単位であり、同一 origin の異なるパスにも共有され得ます。「この端末だけ」は同一 origin 内での共有範囲や、ブラウザデータ消去で失われること、バックアップ対象外であることも説明してください。storage イベント／BroadcastChannel 等と再読取、失敗時のフォールバックを検討し、対応しない場合は制約を明記してください。異なる origin やブラウザプロファイル間で同期するという意味ではありません。
- 非同期操作の競合（選択連打、導入・削除中の再選択、作品切替、別タブ更新、FontFace 完了の逆順）では、古い処理が新しい意図を上書きしないこと。描画し直しによるキーボードフォーカス消失にも注意。IDB 無効・容量不足・localStorage 禁止・Web Crypto／FontFace 失敗では、現在の表示を壊さず、状態と再試行方法を示してください。過大なファイルは読み込み前にサイズを拒否し、digest 等の例外も UI で扱うことを推奨します。

## 4. 字形と読み物

- Galmuri11 は今回の作品名4言語の**各文字**を持ちますが、文章全体や読みやすさの保証ではありません。今回の固定ファイルでは例として `你好` の `你` と `❤ 🎵` が不足。端末 fallback や絵文字表示は環境で変わります。
- Dot＋Neo は CSS スタック順に**文字単位**で代替され、両方にある字は先の Dot が使われます。「日本語は Dot、韓国語は必ず Neo」とは保証できません。分解 Hangul `픽` は結合表示未検証です。Press の指定ファイルは Latin subset であり、日本語・中国語・韓国語の作品名は通常フォールバックです。
- 日英中韓の見本、狭幅・長い作品名、縮小、混在・記号、フォールバック、見切れ、コントラスト、ズーム、スクリーンリーダーとキーボードを確認し、各言語の読み手と実機で評価してください。字形や可読性の評価が済むまでは「作品の正式な推奨書体」と断定しません。
- カタログ表側は作品の意図・概念を短く、裏側には候補の背景・選定基準・出典・ライセンスへの導線を Wikipedia 的な読み物として置く案です。[草案29](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/cb21da9bd4b7edab1de569f4f673acb8ddd13356/docs/re-modern-research/29-pixel-console-reader-front-back-2026-11-07.md)を利用できますが、公開文案としては未承認。候補・由来・現在の評価・未確定部分を分け、フォントの同梱や採用を暗示しないでください。PWA 側の既存 UI に適した導線はお任せします。
