| 条件・操作 | この試験で確認した結果 |
|---|---|
| 同一タブ、Web Locksあり：選択準備→同候補を削除 | 削除はlock待ち。選択は `superseded`、削除成功、選択空、ファイル `absent` |
| 同一タブ、Web Locksなし：同じ順序 | 削除を先に完了させても選択は `superseded`、選択空・表示オフ |
| 同一タブ：準備→オフ | Locksありでは待機後、なしでは先にオフを完了。双方とも古い選択は `superseded`、選択空・表示オフ |
| 同一ブラウザの2タブ、Web Locksあり：A選択準備→B削除 | Bがlock待ち、解放後A選択成功→B削除成功。両タブの選択は空・Aの表示オフ、ファイル `absent`、A再読込後もオフ |

2タブの場合、同じタブの世代取消とは異なり、先に開始したAの選択が成功してからBが削除する順序です。**この試験では前回の条件で選択の復活は再現せず**、不正な全体設定も保持されました。テストSHA-256 `12edc00e34584b888dd92ed7821662390b601e0373162f02bd0ef322f6c3c5a4`。実書体は同梱していません。実行環境・依存関係と固定対象を試験ファイル冒頭に記載しています。

実際の頻度や一般的な安全性の証明ではありません。Web Locksなしの**複数タブ**、待機・失敗の組合せ、UI操作、実機や他ブラウザは本試験の範囲外です。15秒制限は先方実装の書体準備に関するもので、すべての保存・復旧や待機が15秒以内に終わるという保証ではありません。

## 2. 手間なく適用・取り外し・削除するための提案

作品と題字を主役にし、既存の書斎・基地・本文・ノーツ等の設定を勝手に変えないことを優先します。明示的な全体書体設定を優先し、作品連携は別途オン。次はPWA側との設計相談であり、実装済みとするものではありません。

1. **選ぶ／適用する／取り外す／ファイルを削除するを区別**。適用前にプレビューと影響範囲を示し、既存設定を変えることなく戻せる動線を用意。取り外しは原則ファイルを残し、再適用を簡単に。ファイル削除は別操作で容量・共有参照・他作品への影響・残存設定を明示し、必要時に確認する。
2. 導入は利用者の明示操作から始め、自動取得・自動適用を既定にしない。失敗しても以前の表示や設定を守り、待機・取消・成功・失敗・結果不明を区別。複数タブで待機する場合は原因と、可能な中止・再確認の方法を示す。取消後も準備がいつまでも占有しないか、保存後の適用失敗と中断・再読込の整合も別途設計・試験する。
3. 削除時に実際に消えるものと残る選択、作品連携設定、キャッシュ等を画面上で説明し、失敗や部分状態から安全に再確認できるようにする。壊れた保存は生データを勝手に外部送信・上書きせず、利用者が退避／復旧／削除を選べる案内を検討する。
4. 作品欄には、まず説明と既存題字設定への導線を置く段階案を維持。専用受け口、一体コンテナや容量上限の緩和は、安全性・容量・信頼境界・互換性を別々に検討し未決。単に入口を変えても安全性の向上や容量緩和は成立しません。
