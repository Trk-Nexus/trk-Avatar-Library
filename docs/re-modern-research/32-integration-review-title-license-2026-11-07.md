## 結論：題字を主役に、書体情報は辿れる形で

- 作品一覧の主役は**作品名・題字の見え方と作品の意図**。フォント名の羅列を題字より大きく見せず、作品の裏側／詳細の「書体とライセンス」へ辿れるようにする。
- ただし、フォント名を隠したり、ライセンス本文だけから利用者やプログラムが読み取る前提にはしない。**実際に使う書体名・状態・適用箇所を、ライセンスへの入口で人が読めるように明記**し、別々の書体には各全文・著作権表示を対応させる。system 系は端末依存で、具体的なフォント名を推測しない。
- **機械が連携するID、表示名、実ファイル、ライセンス全文は別物**。表示名を機械IDや権利条件の代わりにせず、現行PWAの候補IDと個別素材を対応づける。候補の導入・適用は利用者が選び、作品を選ぶだけで本文・書斎・基地・ノーツを変えない。
- 以下はPWA側と確認する推奨案。書体の最終決定や形式変更をここで既成事実にしない。[回答31](31-pwa-trk315-consolidated-response-2026-11-07.md)は旧PRの固定版に対する記録であり、今回のPWA mainとは区別する。

## 2. D1：作品と書体をどうつなぐか

レビューにある通り、現在は次が別の名前空間です。

1. PWA作品形式の `heading.font` は `system`／`dotgothic` だけ。`dotgothic` が **Dot＋Neo** を意味するとは決められない。
2. PWA題字設定の候補IDは `galmuri`／`dotneo`／`press`。`dotneo` は複数の固定ファイルの**組**。
3. Avatar の [`pixel-console-font-contract.json`](pixel-console-font-contract.json) は `dotgothic16-japanese-400` 等の**素材単位**の研究契約で、PWA形式ではない。

**推奨：候補IDと構成素材IDを分離して対応表で結ぶ。** PWA の既存候補IDを連携の候補キーとして再利用する方向が最も簡単ですが、正式な契約・version・管理主体・固定版の更新・削除・別作品の利用・未知IDの扱いは両側で合意してください。表示名やライセンス文章からIDを推測しません。`heading.font: "dotgothic"` を勝手に `dotneo` に変換せず、将来の題字用参照は見出し設定と意味を分ける。`heading.font` の廃止は、既存データ・未対応版・更新の移行が設計できるまでは行わない案です。

例として `titleFont: "dotneo"` を新設することは**将来の候補案にすぎず、現行の pack.json に入れない**でください。固定 PWA `1fd6a89` の `checkManifest` → `cleanWork` は未知項目を静かに捨てるため、書いても読み戻せません。`heading.font: "dotneo"` は `bad-heading-font` で拒否されます。構造テストの再現は §5。新たな欄を実装する場合、少なくとも次を一緒に設計します。

- フィールドの役割（作者の**推奨**なのか、利用者が選んだ実適用なのか）・省略値・未確認作品の扱い。manifestにIDがあるだけでダウンロード・導入・適用しない。
- 版、許可リスト、型・長さ、知らない／無効なID、旧版が無視する場合の通知、保存・読戻し・再起動・移行。任意 URL・CSS・JS を作品から実行／取得しない。
- 各候補の固定ファイルと各ライセンス、必要な字種・容量・fallback、ユーザーによる導入・選択・削除・更新。複数作品で共有する素材を、参照中に誤って削除しない。
- 候補の説明は一箇所の版付き対応表を基準に作り、Avatar・PWA・実バイナリ・全文を相互照合。正本の場所と変更手順は共同で決める。ハッシュ固定版の更新は明示的に管理し、表示名の同一だけで一致とみなさない。

PWA `fontForWork()` は現状、保存された**作品側の候補を全体設定より優先**して返します。戻り値はIDのみで、画面適用・ロードの成功を示しません。コードコメントは呼び出し側に `ready()` と同じ確認を求めていますが、`ready` 自体は公開APIに含まれません。実装時は検証／ロード・所有・解除・失敗を扱える公開インターフェースを別途設計してください。

## 3. D2：明示設定・作品指定・オフの優先

基本案は **利用者が明示した全体の題字書体 ＞ 利用者が明示して有効化した作品連携 ＞ もとの表示**。全体設定は共通題字と全作品カード、作品連携は共通題字と対象作品カードだけ、という2つの独立した機能として説明する案です。他作品・本文・書斎・基地・ノーツ・既存の保存設定は変更しません。背景・既存スタック・他設定が変わった場合に古い値を機械的に書き戻さず、現在の通常表示へ戻す設計を検討します。

| 利用者の状態 | 題字の期待例 |
|---|---|
| 全体も作品連携も未選択／オフ | 既存の題字・既存の設定を維持。書体ファイルの自動取得なし。 |
| 全体 Galmuri を明示、作品側 Dot＋Neo も有効 | **全体 Galmuri が優先**。作品指定や保存値は破壊しない。 |
| 全体の拡張を解除、対象作品で連携を別途オン | 対象作品についてのみ、検証・ロード可能なら作品候補。ほかの作品は既存表示。 |
| 未導入・破損・未知・ロード失敗／対象作品から離れた | 部分適用せず、現在の利用者設定に基づく安全な既存表示。理由を示し再試行可能にする。 |

**「使わない」の意味は設計上の未決点です。** 現行PWAの空選択は全体機能のオフですが、利用者が「どの作品でも拡張を使わない」と受け取る可能性があります。全体だけオフにして作品側が自動的に現れる仕様にするなら、その範囲を明記し、作品連携は**別の明示操作**を必須にする。全拡張を止める操作も提供する案を推奨します。現行保存値だけでは「未設定」と「明示的にすべて拒否」を区別できないため、移行時に既存のオフ利用者へ自動適用しないこと。表示文・設定・マイグレーション・オフライン・多タブを揃えるまで決定扱いにしません。

### 追加で確認できた選択失敗の境界

PWA main の `choose()` は、欠落・hash不一致なら以前の選択を保ちます。一方、`ready()` は在庫と hash を調べ、**FontFace.load() の前に選択を保存**します。合成データ・模擬 FontFace で次候補のロード失敗を注入すると、戻り値は `ok: true` でも選択は新候補、画面状態は `error` となり、以前の拡張は解除されました。これは**模擬障害下の再現**で、現実のブラウザでの頻度を示しません。

推奨は必要な全ファイルの検証とロードを終えてから新選択と表示を確定し、失敗・保存不可・競合時は旧選択／旧表示を保持しつつ理由を返すこと。旧選択自体が失われた場合は安全な通常表示へ戻す。`seq`・多タブや保存処理の原子性との整合も検査する。PWAの現行実装をこの文書だけで変更したものではありません。
