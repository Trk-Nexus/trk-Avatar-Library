# trk-re-modern：背景と「選ばなかった案」を活かす方針案

2026-11-07 ／ **依頼者との検討用。提案であり、PWA 側の仕様決定・実装依頼・作品の登録や公開ではない。**

[PWA からの質問](https://drive.google.com/file/d/1MiZxrtq2UTMnYMv22DNzIdVRDe-jWo8d/view)への回答を考えるとともに、依頼者が提案した「概念の説明と、書体・構図などの別案を切り替えて楽しめる仕組み」を整理する。

## 1. このカテゴリーで何を目指すか

作品を、固定された配色だけではなく、**概念から、書体・色・面・構図・操作へ至る選択の理由をたどれる体験**として扱う。制作者が重視した見え方は残しつつ、検討した選択肢を紹介し、実現・検証できるものは利用者が明示的に切り替えられるようにする、という方向を提案する。

ただし「候補として説明すること」と「切替機能として提供すること」は別。候補だから必ず実装・配布しなければならないわけではない。未確認の素材、危険な点滅、操作や解除を妨げる表現を、説明だけで無条件に提供してよいことにもならない。選択の自由と安全な利用を両立させたい。

## 2. PWA の質問への暫定回答

### Q1. 実画像だけを除外し、グラデーションは背景色だけで判定する現状で十分か

**背景色だけでは、グラデーションが文字の背後にある場合の対比を保証できない。** 一方、この指摘は「既存の `.screen` の淡い光が実際に危険だった」という測定結果ではない。実画面の重なりと色を別途確認する必要がある。

確認した対象は PWA の PR #105 head `b1731aa76b29d579923b0568ffa79286a0a95726`（確認時点で未マージ、main は trk311）。`js/remodern-paint.js` の `effectiveBg` は祖先の `background-image` に `url(...)` があれば `null` にする一方、グラデーションの描画自体は合成せず `background-color` を重ねて判定する。質問にある smoke 14 OK は PWA 側の報告であり、Avatar が実行した結果ではない。

**計算上の反例（実画面の不具合の再現ではない）**：黒 `#000000` の上に白20%から透明へのグラデーションを重ね、文字 `#767676` を使う場合、黒だけとの比は約 **4.62:1** で PWA の 4.5:1 判定を通る。白20%の位置は通常の sRGB 合成の単純な仮定で `#333333`、この位置の文字との比は約 **2.78:1**。PWA の `effectiveBg`／`titlePaint` を模擬 DOM で呼び出して背景が黒と判定されることと、色比を計算した。実ブラウザの画素、実スキン、文字がその位置にあることは測定していない。**「淡い」だけでは閾値近くの文字に十分とは限らない**ことを示す例である。

また、`url(...)` 検出は特定の CSS 背景を保守的に扱う有用な一歩だが、他の画像表現、疑似要素、重なった別要素、動画・canvas・透明・フィルタなど、あらゆる背景の検出や安全性を証明するものではない。画像の位置によっては文字を遮らないこともある。既定色に戻す動作は「作品色を使わない」ことであり、その既定色自体の可読性まで自動で保証するものではない。

### Q2. グラデーションを一律に使わない方針か

**グラデーションそのものを一律禁止する案には反対。** 背景や作品の表現はなるべく保ち、題字色の適用を次のように場合分けする方向を提案する。どの方法を採るかは PWA 側と具体化する。

1. **条件を把握できる場合**：実際に文字の背後となる領域の合成色・変化範囲を評価し、題字の文字とアクセントそれぞれに、許容した全範囲で対比を確認して作品色を使う。グラデーション端点だけの確認は不十分な場合がある。背景色、透過・複数層、位置・サイズ、変更後の再判定を含む。任意の CSS をすべて正確に解析できると仮定しない。
2. **評価が難しいが作品色を活かしたい場合**：装飾を画面から消さず、文字の背後に作品の意図に合う、対比を確認した不透明な面を設ける案を検討。作品の構図・見え方を変えるため、適用箇所、既定、切替、強制色、既存の画面への影響は PWA と利用者の合意・実測が必要。面だけで必ず安全になるとは限らない。
3. **評価できない場合**：作品色の自動適用だけを保留し、既存の表示に戻して理由を示す。背景や作品自体の禁止ではない。既存表示も必要な読みやすさを別に確認し、安全な操作・解除を守る。将来は評価可能な条件を増やし、表現の幅を広げる。

特定の薄いグラデーションについては、まず実スキン・実際の重なり・文字位置に即した評価を行い、方法を試作する。上の案は**今すぐ全グラデーションで作品色を止めることの決定ではなく**、不明な場合の扱いと検証可能な適用経路を詰めるための提案。

### Q3. 確認方法

- 題字の本文と `!` それぞれについて、PWA が現在採用する **4.5:1** を目安に、実際に文字の背後へ重なる色を確認する。数値は計算・測定で示し、目視だけで「4.5:1」と断定しない。文字の大きさによる基準差はあるが、PWA が既に使う 4.5:1 を今回の検討目安とする。
- 単色の明暗／閾値付近、淡い・強いグラデーション、文字位置での中間色、半透明パネル、複数レイヤー、画像・動画など未知の背後、明暗スキン変更時の再判定を対象にする。点や端点だけの抽出・スクリーンショットの一枚だけで全範囲の保証としない。必要なら題字範囲を覆う背景の**保守的な色域全体**を評価する。
- 実際の題字は選曲画面の `.brand h1`。題字に加え、将来書斎・基地に作品色を広げるときは、その領域の外枠・操作・警告・フォーカスを別に試す。書斎本文の既存テーマや文字設定、基地の映像・字幕・再生・退出は守る。
- 画面幅・題字の折返し・200%拡大、言語・字種、透明合成、forced colors、キーボード・タッチ・読み上げ、スイッチと解除、オフライン・保存失敗を確認する。OS／ブラウザ／実機や支援技術による差、人による見やすさを記録する。
- PWA の `docs/REMODERN-DEVICE-CHECKLIST-2026-11-07.md` は有用な確認案だが、数値は目視だけで判定できない。書斎・基地の色適用は現段階で未実装の報告なので、対応前の項目を未実施／対象外と区別して記録する。

## 3. 検討の履歴と、実際に選べる別案

作品紹介には、各選択について **目的／検討案／採用または保留の理由／対象領域／見本と実装の状態／出典・権利／確認・未確認／選び直し方** を記す。「昔こう考えた」という履歴と「これからの新提案」は分ける。

「ピクセル・コンソール」の現時点の記録例：

| 要素 | 記録にある選択肢・意図 | 現状 |
| --- | --- | --- |
| コンセプト | `pixel-8bit` の暗い舞台と角形を出発点に、「ドットの秩序は残し、読むための文字は犠牲にしない」。特定機種の復刻ではない。 | 作品は依頼者に承認済み。正式台帳への登録・公開・所定のレビューは別途必要。 |
| 見出し書体 | DotGothic16 Regular 400 は日本語の短い見出し向けの候補。旧作指定の Press Start 2P も調査したが、日本語見出しとの一貫性を考え前者を優先候補とした。 | 現在の制作データ・見本は system 系。どちらの候補も新作品にロードしていない。字種・権利・ファイル供給・代替・解除は要確認。既存の `電子ゲーム` 組は書体名を指定するが、それだけでフォントをインストールしない。 |

| ノーツ | ドンとカッを暖色／青と異なる形で提案。 | 明示的な既存の「スキンのおすすめ」は共通ノーツ設定に保存され、スキン変更で自動復元されない。今回の選択肢機能で勝手に変更しない。 |

### 新しい体験の提案例（未実装）

- **作品の「表現バリエーション」**：例えば静かな面を中心とした案と、装飾を少し強めた案を同じ概念の異なる解釈として見せる。これは今後の構想であり、過去にこれらの具体的なレイアウトを比較・承認したという意味ではない。
- **書体の選択肢**：制作側の意図を説明し、利用者は現在の書体を維持する、対応・権利確認済みの短い見出し候補を試す、などを選べるよう検討する。本文・読書設定は自動変更しない。書体のロード失敗時の代替、容量、字種、ライセンス、復帰を説明する。
- **構図・背景の選択肢**：文字の周りに落ち着いた面を置く／装飾を離す／余白や密度を変える、といった見え方の比較を検討する。プレビューの段階で分かりやすく「この画面だけ」「未実装」等と明記する。単に中央寄せなど複数案が以前に作られたとは主張しない。
- 作品紹介の「どうしてこの形？」から、デザインの狙い、候補とトレードオフ、可能なら静止した比較見本を辿れるようにする。見本に偽の適用ボタンを置かない。

いずれも現在の作品 pack にフォント・構図の切替機能が実装されている意味ではない。切替を設けるか、作品ごとの固定バリエーションにするか、独立設定にするか、組み合わせをどこまで許すかは、実際の使いやすさと PWA の実装・データ形式を見て合意する。

## 4. 実装を検討するときの約束（提案）

1. **プレビューと適用を分ける。** 操作前に対象領域と変わる設定、書体の取得や通信、容量を表示。選んだだけで保存せず、明示適用・取り消し・直前状態への復帰を可能にする。保存失敗時は元に戻し、見える形で通知する。
2. **既定と優先順位を守る。** 現状維持から始め、利用者が既に選んだ書体やアクセシビリティ設定を上書きしない。作品推奨、利用者の上書き、OS の強制色等の優先関係と、作品切替・解除時に何が戻るかを PWA と決める。設定が変えられない環境では、失敗・理由・代替を示す。
3. **領域を混ぜない。** 共通・書斎・基地は独立選択／現状維持を守り、本文テーマと文字設定、再生・映像・字幕・退出は保護。ノーツおすすめの既存動作は変えない。
4. **内容と信頼の境界。** 任意スクリプト・CSS・URLの実行や、追加権限・自動外部通信を当然としない。配布物の型・許可値・容量・バージョン、未知の項目を旧版が読む場合、保存・バックアップ・互換・復元、登録 ID と配布物の認証を別途協議する。
5. **説明可能でも安全は別途検証。** 対比・文字拡大・フォーカス・停止・解除・forced colors・reduced motion・キーボード・読み上げ・実機、画像・動画、言語・字種・権利を各案で評価する。性能やアクセシビリティの希望を一括設定に勝手に押し込まず、個別の選択肢や代替を検討する。

## 5. 次に決めたいこと

まずは **作品紹介で選択理由と候補を見せることを先行**し、その後、ピクセル・コンソールの「書体」または「文字背後の面・構図」から小さな切替見本を作る、という進め方を提案する。最初は実データを変えない試作用の見本として比較し、PWA 側の設定・作品形式に反映する前に優先順位・保存・解除・権利・安全性について一緒に決める。

依頼者からの追加提案を踏まえ、切替見本の「裏面」で概念と出典を読み、開発中の調査や判断も辿れるようにする[文章見本](05-concept-reverse-pixel-console-draft.md)を用意した。2026-11-07、依頼者は**開発メモを未整理でも残し、公開向けの読み物とは分ける**方針を了承し、[コンセプト](../trk-re-modern-concept.md)と[紹介書式](../trk-re-modern-introduction-template.md)へ反映した。具体的な文章・切替UI・各候補や、上記グラデーション案は引き続き検討中で、実装や公開はまだしていない。

PWAへの暫定回答は上記 §2。依頼者と方向を相談してから、確定部分と検討中の部分を分けて共有する。
