# 書体拡張の選択・保存・解除・復元：状態モデル

2026-11-07／[対象・依存関係の案](20-font-scope-dependencies-2026-11-07.md)に続く[進捗計画](19-remaining-roadmap-2026-11-07.md) A 節手順2。**隔離した純粋な状態モデル**であり、PWA で実行・保存する機能、利用者向けUI、実際の書体の検証・ロード、複数タブの同期を実装したものではない。仕様の合意・作品の正式登録／配布も意味しない。

## 判断のために分ける状態

[モデル](pixel-console-font-state-study/model.mjs)は実ファイルや個人設定を持たず、与えたイベントから次状態と**将来のホストが実行すると仮定した操作**を返す。試作の識別子 `v1` 等は仮の記号で、実際のバージョン・SHA-256・作者認証には使わない。

| 軸 | この研究モデルの状態・意図 |
| --- | --- |
| 作品選択 | `keep`（現状維持）／`pixel`（対象作品）／`other`。対象を離れると進行中のロードを取り消し、試作側の適用を外す。作品そのものの表示や保存を変更するモデルではない。 |
| 利用者の優先設定 | `unknown`／`yes`（既存の題字書体を優先）／`no`（優先指定なし）。不明・優先ありの場合は作品書体を適用しない。優先を解除しても自動適用せず、改めて明示的な適用操作を待つ。 |
| 拡張の保存 | `unknown`／`absent`／`present` と仮の内容識別子。起動時や競合後は不明として、書き込みの決着を含む**整合した再読取**が必要。保存だけでは書体を使わない。 |
| 実行中の処理 | 保存・削除・整合読取は1件ずつ。書体読込は別トークンで管理し、**検証とロード**→**対象への適用**の二段階。どちらも成功したときだけ `active`。保存・削除が確定したら旧ロード・旧適用を無効にする。 |
| 表示 | 成功時は候補の題字のみ。未導入・失敗・解除では作品書体を表示せず、既存の表示を維持。ステータス語は実装例ではなく、利用者に意味が伝わる案内文・操作は別途設計する。 |

両書体とそれぞれのライセンスが揃い、検証とロードの**両方が成功**してから適用するという安全側の候補を扱う。ただしモデル自身はハッシュ・ライセンス・FontFace・DOM を検査していない。「成功」イベントはそれらと対象への適用が実際に成功した後に、ホストが正しく発行するという仮定。旧 PWA・未対応時の検出と表示 UI も未実装。

## 遷移と期待結果

| 出発状態・明示操作 | 期待する遷移と案内 | テスト・限界 |
| --- | --- | --- |
| 起動直後 | 作品は現状維持、優先設定・保存状態は不明。読取に成功し、優先設定が確認されるまで作品書体を使わない。 | 純粋モデル。既存 PWA の初期動作とは異なる研究用の初期値。 |
| 対象作品を選択、拡張がない | 書体の適用要求に対し「拡張が必要」。既存の表示のまま。作品の導入自体を停止しない。 | モデルで確認。案内 UI・適切な翻訳は未実装。 |
| 拡張を保存だけ | 確定した保存の後は「保存済み・未適用」。対象作品や既存の書体、他パックは切り替えない。 | モデルで確認。隔離 PWA で内部の保存 API を使った[研究18](18-scoped-font-prototype-2026-11-07.md)もあるが、現在の利用者向けパック入力は即時有効化する。 |
| 対象作品・優先設定確認・拡張あり → 適用 | 検証・ロードの後、対象への適用成功を確認してから有効とする。読込中・適用中はいずれも成功表示にしない。 | モデルの二段階を確認。研究18の実 FontFace 実験とは独立で、両者を接続した試験ではない。 |
| ファイル・ライセンス不一致、読込失敗、適用先の競合 | 部分結果を片付け、既存表示を維持し、理由・再試行を案内。ユーザーの優先設定がある場合も勝手に上書きしない。 | モデルの模擬失敗と、研究18の一部の実ロード・インライン優先を別々に確認。実 UI・すべてのフォントエラーは未確認。 |
| ロード／適用中に現状維持・別作品・ユーザー優先設定に変更 | 進行処理を取り消し、後着した成功通知で作品書体を再表示しない。ホストは途中で作った一時資源を必ず片付ける。 | トークンによるモデル上の拒否を確認。実環境の取り消し・遅延した DOM 更新や複数操作の後始末は別実装・別試験が必要。 |
| 有効中にユーザーが別の書体・スキンを選択、あるいは解除 | 試作が所有するスタイル・フォントだけを解放し、変更後のユーザー設定を古い控えで上書きしない。スキン変更自体はモデルでは扱わない。 | ユーザー優先はモデルで確認。研究18は実PWAでインライン題字書体と1種類のスキン変更を限定確認。 |
| 新しい拡張の保存／置換に失敗し、ロールバックが**確定** | 既存の保存・有効書体を維持し、失敗を案内。 | モデルで確認。実ストレージが原子的に失敗前へ戻った証拠は未確認。 |
| 保存結果が不確か／別タブ等から変更通知 | 旧書体を外し、保存状態を不明にして整合読取を要求。過去の完了通知だけで有効化しない。 | モデルでは通知と結果を注入。実際の同期・順序保証は未実装。 |
| 保存／置換が確定 | 古い読み込みや適用を取り消す。同じ識別子でも内容が変わり得るので再検証し、**自動適用しない**。 | モデルで確認。実際の版・ハッシュ・原子的置換と利用者への案内は未実装。 |
| 拡張の削除 | 利用者の確認後に削除を要求。確定後に関連する適用を外し、作品の選択自体は保持。ロールバック確定なら削除前の状態を維持。 | モデルで確認。実装では他作品の共有依存、削除中の利用、失敗・取り消しを追加設計する。 |
| 再起動 | この研究モデルは作品選択や適用の永続化を実装しない。現状維持／不明から開始し、保存状態・優先設定を再確認する。 | **自動復元できることは未検証**。実際に選択を復元するか、再同意を要するか、通知・破損時を今後決める。 |

`save-start`／`delete-start` は利用者が明示的に操作したと仮定する。現在の案では新しい保存が完了しても直ちに書体を適用せず、改めて適用操作が必要。将来は事前説明と同意を伴う一体操作も候補であり、このモデルの操作数を最終UI仕様としない。

## 競合・資源解放の前提と未解決

- トークンは**モデル内の後着イベントを拒否するだけ**で、IndexedDB の書き込みを取り消したり、他タブの更新・別セッションの値を止めたりしない。外部変更や結果不明時は、ホストが処理の中止・確定を整理し、相互排他／版の照合などにより整合したスナップショットを取得してから結果を返す必要がある。保証できなければ不明のままにする。モデルはこの協調方法を実装していない。
- 読込・適用途中の取り消しや後着成功では、拒否した結果が持つ FontFace・Blob URL・一時 DOM を**実行側が責任を持って片付ける**必要がある。トークンを拒否しただけでは物理的な後片付けは証明できない。既存ユーザーや別作品の資源を消さない仕組みも必要。
- `storage-rolled-back` は「失敗した」という通知だけでは不十分で、ホストが旧レコードの維持を確認できたときに限る。確定できないエラーは `storage-uncertain` として無効化・再読取する。
- ユーザーの設定と競合時の検出、通知と再適用、複数領域・作品での共有参照、保護対象の範囲、古いタブが保持する資源の開放は未解決。研究18のコントローラーとこのモデルは別物であり、連動・永続化・本番安全性を主張しない。

## 再現できる試験と次の作業

```sh
node --test tests/re-modern-font-state-study.test.mjs
```

10件のテストで、初期の不明・未導入、保存のみ、ユーザー優先、取消しと後着、二段階の適用失敗、確定ロールバック・結果不明、置換・削除、同一IDでの置換、再起動、1万件の決定的なイベント列に対する不変条件を検査した。これは**擬似イベントだけ**を入力した試験で、実ストレージ・実装アダプター・画面 UI・複数タブ・アクセシビリティ・権利判断は検証していない。

次は、複数ライセンスの利用者向け表示と出典・配布形態の整理を並行して進め、モデルと実際の隔離試作の接続に必要な処理・復元・排他を設計する。完成候補が整うまで PWA へ連絡せず、正式登録・公開を行わない。
