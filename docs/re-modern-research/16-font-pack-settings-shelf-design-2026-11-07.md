# 作品の書体を「読み込む拡張」と設定棚で扱う案

2026-11-07／依頼者の提案を受けた Avatar 側の設計メモ。**作品ファイルに全フォントを詰めることを前提にせず**、既存のカスタムパックのように利用者が書体入りの拡張を選んで読み込み、作品の完成後に PWA 側へ設定棚と作品別の利用方法を相談する。PWA に依頼・仕様変更・連絡をした記録ではなく、相手方が実装に合意した意味でもない。

## 既存の土台：実際にあること

調査対象は PWA main [`4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6`](https://github.com/Trk-Nexus/trk-PWA/tree/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6)（確認時の main）。将来のバージョンは再確認する。

- 設定のパック欄に `.stpack`／`.zip` を選ぶ入口、使用中のパックを外す操作、容量表示・削除がある（[index.html](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/index.html#L1439-L1483)）。この画面のファイル選択は保存だけではなく、`installAndUse` を呼ぶ（[custom.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/custom.js#L1192)）。他の入口もすべて同じ動作とは限らない。
- 既に**入っているパックの書体索引**があり、検索・表示と「使う」操作がある。現状は書体行の「使う」が個別の書体を独立に指定するのではなく、その**パック全体を有効化**する（[pack-catalog.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/pack-catalog.js#L523-L564)）。新しい棚を必ず一から作るのではなく、既存棚の拡張も選択肢。
- カスタムパックは `shadow-taiko-pack` version 1 の `fonts` と WOFF／WOFF2 を受け付け、書体だけのパックも扱うコードがある。書体は FontFace として登録し、外す際に登録と URL を後片付けする。対象の `licenseFile` も格納できる（[custom.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/custom.js#L173-L184)、[同登録部分](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/custom.js#L325-L389)）。固定版の宣言上は1パック最大8書体、1書体16 MiB、パック500 MiB・保存合計1024 MiB。容量設定と端末の空き容量に依存する。これらは**通常のカスタムパック**の制約であって、作品ZIPの256 KiB上限とは別。
- 既存の [DotGothic16 パック](../../font-packs/dotgothic/pack.json)は実際にスキンとノーツも持つ。書体だけが適用されるものではない。一般形式に書体だけのパックを作れることと、この既存パックを作品用にそのまま使ってよいことは別。
- 既存目録の方針では目録もパックも利用者の選んだファイルを読み、自動ダウンロードしない（[pack-catalog.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/pack-catalog.js#L1-L12)）。作品拡張でも利用者の明示選択を基本とする。

## 現状のままでは作品の見出し用には足りない点

1. 書体だけのパックでも、現在の実装は有効な書体をスキンの **`--font` の先頭に設定**する。特定作品の題字だけには限定しない（[custom.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/custom.js#L679-L681)、[core.js](https://github.com/Trk-Nexus/trk-PWA/blob/4f93a69f94ec3a3c14c6ea8d1cf9c064723b43e6/js/core.js#L2230-L2236)）。共通・書斎・基地・本文を守る作品方針と区別が必要。
2. パック有効化では先のパックを外してから切り替える。既存パックと作品専用の書体を別々に独立して重ねる挙動は、この仕組みだけでは保証できない。既存のスキン・音・ノーツ・書体設定への影響を具体的に検証する。
3. 既存のパック詳細には複数の書体名が表示されるが、ライセンス全文ボタンは最初の `licenseFile` を選ぶ実装。DotGothic16 と NeoDunggeunmo はそれぞれ別の著作権表示を持つため、**各書体の全文と著作権表示にアクセスできる設計**を検討する（同じ文面というだけで一つの表示にまとめない）。
4. 固定版の PWA の re-modern **作品**インポーターは作品ZIPが256 KiBまでで、書体ファイルを含めることも認めない。一方、上記は別の汎用パック受け口。別ファイルを送れば現在すぐ作品見出しに自動適用できるという意味ではない。
5. 実ファイルを置いておけば自動で利用可能になるわけではない。作品・書体の対応、適用領域、利用者設定の優先順位、依存関係、更新・削除・失敗・復元を PWA と相談する必要がある。

## Avatar 側が完成案として用意するもの（提案）

### 利用者から見た流れ

1. 作品の紹介で、内容・対象領域・必要容量・書体・作者・ライセンス・対応言語／制約を確認。作品と書体拡張は別のものとして説明する。
2. この作品の意図した基本表示に書体拡張が必要なら、作品案内でそれを最初から必要な構成として案内し、利用者が**明示的に**拡張を取得・読み込みできるようにする。拡張を導入しない／使わない選択肢も残し、その場合は代替表示であり見た目が異なる可能性を明示する。どの領域が変わるかも分かるようにする。現行設定画面の選択は即使用するため、保存だけ・適用の分離は未実装の提案。
3. 設定棚でインストール状況、各書体の提供元・ライセンス・サイズ、適用先、欠字や失敗を確認し、利用・解除・削除を選ぶ。必要に応じ利用者が従来の設定を優先できる。
4. 未導入・読込失敗・旧版・削除後は安全なフォールバックと状態表示を用意する。端末依存の代替書体で必ず目的どおり表示されると約束しない。導入前に別ファイルの取得や外部通信を自動で行わない。

### 配布候補と役割

- 作品の記録・色や構成の成果物と、**フォントファイル＋各ライセンスの拡張**を分ける。拡張の具体的な形式は既存 `shadow-taiko-pack` の再利用・互換拡張・別形式を比較し、完成案と PWA 側の相談で決める。別形式を既存 `.stpack` として読み込めるとは仮定しない。
- 見出しの候補は DotGothic16 日本語 WOFF2 396,312 B と NeoDunggeunmo WOFF2 44,352 B の組み合わせ（合計440,664 B、梱包とライセンス分を除く）。サイズと字形の限定検証は[研究15](15-korean-font-fallback-study-2026-11-07.md)。一つの拡張に二書体を収めるか、それぞれを共通資源にするかは未決。
- パックに収めるなら書体本体の固定版、SHA-256、作者、取得元、各 OFL 全文・著作権表示を添え、導入可能なファイルが作品とどう対応するかを明記。識別子の重複、同じ資源を使う別作品、更新・既存ユーザーとの衝突、保存容量を検討。最終的な権利判断・配布承認は別に行う。
- 作品導入後の標準表示は配布しやすい基本書体で成立することを目標としつつ、同梱できない任意の別書体は[利用者自身の取得・利用条件と見本画像の許諾](14-font-distribution-and-user-choice-2026-11-07.md)を個別に確認する。別書体がなくても基本作品は使えるようにする。

## PWA へ相談する時の論点（完成案ができてから）

- 既存の書体索引の拡張で足りるか、作品用の設定棚が別途必要か。取り込みのみと適用の切り分け、容量・出典・ライセンスの提示、利用者設定や支援技術との関係。
- 作品名・見出しに限定した書体指定と複数書体のフォールバック順。既存の通常パック／スキン・本文・ノーツを壊さず、作品を外した際に**その後利用者が変えた設定を上書きせず**元に戻せるか。
- 手動導入、依存する書体がない場合の案内、異なるバージョン・旧版・複数作品の共有、保存失敗・部分的ロード失敗・削除・再起動・オフライン時の扱い。
- 複数の異なるライセンス全文と著作権表示を個別に閲覧できるか。フォントファイルの検証・容量・名前衝突・メモリ・セキュリティ、フォントパックの選択を強制しないこと。
- 作品案・実ファイル・表示見本・出典・バージョンとハッシュ・対象文字・用途・手順・自動試験と人手確認・未確認を添える。PWA 側の仕様や都合を先に決めつけない。

**続き**：[二書体の汎用パック形式による隔離候補](17-isolated-font-pack-candidate-2026-11-07.md)を再現生成し、固定 PWA で読込・解除・既存パックとの切替を限定試験した。見出し限定・権利情報の提示などは残り、正式配布物ではない。

設定棚の受け口を待つのではなく、二書体を含む配布可能な完成候補の形・権利表示・複数ライセンスと容量を整理し、作品内の見出し範囲・依存／失敗・復元・利用者選択を設計・検証する。現段階は提案と研究であり、拡張の正式配布、PWA の機能実装、作品の正式登録はいずれも行っていない。
