# trk-re-modern：表現の自由と拡張機能の境界

2026-11-07 ／ 依頼者の方向性を記録。**制作方針と将来の検討案であり、PWA の機能追加・権限付与・配布仕様・公開の合意ではない。**

## 1. 方針

Avatar Library の re-modern は、PWA の現在のオフライン完結・既存受け口だけに発想を限定せず、必要な場合は大きな素材、追加機能、通信や別実行環境を含む作品も責任を持って研究する。そうした作品の紹介を PWA から参照できても、導入するか・追加機能を使うかは利用者が明示的に選べる形を目指す。

**研究の自由と、他のアプリ・利用者への権限付与は別。** PWA 側の既定・運用方針・オフライン利用を Avatar 側だけで変更しない。動作に PWA の追加受け口が必要なら、目的と影響を具体化して PWA と合意する。PWA に合わないものは、紹介だけにとどめるか、別の実行環境を検討できる。作品に対する承認は新しい機能・権限・公開の承認ではない。

標準のスキンはデータとして扱い、選んだだけでネットワーク、任意コード、追加権限や外部ソフトの導入が始まる前提にしない。例外は用途別に別途設計・審査・利用者の同意を必要とする。既存の [制作ガイド](../trk-re-modern-guidelines.md) にある安全・権利・検証・公開条件を守る。

## 2. 目指す作品の幅（例であり、機能仕様ではない）

| 方向 | 例・目的 | 守ること・未決定 |
| --- | --- | --- |
| メディア中心 | 再生・字幕・操作に集中し、ゲーム UI を前面に出さない見え方。 | 非表示と機能・データの削除は別。戻る方法、再生・字幕・退出、ユーザー設定を保護。 |
| 用途特化 | 音楽再生、時計、作業補助など、アプリやユーティリティのような使い方。 | 何が作品で何がホスト側の機能か、権限・依存・オフライン時の動作を分ける。 |
| デザイン・概念 | 絵画・文学・図柄・歴史から着想した表現。 | 出典・史実と解釈を分け、画像・文章・書体の権利と再配布条件を個別確認。 |
| 自由な構成 | Hyprland 等の構成思想に着想を得た、配置や画面構成を利用者が選べる体験。 | そのソフトの機能を再現・連携できるという意味ではない。既存設定・操作・復元を守り、実現方法を別途検討。 |

共通・書斎・基地は独立選択と現状維持を守り、作品の選択で読書本文設定、共通ノーツ、再生設定を勝手に変更しない。既存の「スキンのおすすめ」ノーツ操作の挙動はそのまま。実際のプレビュー、設定追加、各領域の適用は現時点で未合意・未実装。

## 3. 拡張機能ごとの設計上の論点

どの経路も**将来の検討**。機能や権限は実装・審査・利用者の承諾後に初めて使える。PWA の現行作品形式に下記の項目があると意味しない。

| 例 | 候補となる受け口・注意 |
| --- | --- |
| 大きな書体・画像・データ | 内容・容量・ライセンス・出典・ダウンロード先・更新・削除を事前に示し、必要なものを選択して取得する。取得しない／失敗／オフライン時の軽量な代替を用意する。追加権限や通信は別途同意。 |
| 端末の時刻 | ホストから限定的に現在時刻を渡す等の案。一般的なブラウザの時計取得は通常特別な権限を要求しないが、時刻帯、切替、時刻変更、表示・停止の影響を検討。時刻と位置情報は同一ではない。 |
| 外部 API・ネットワーク | 通信先、目的、送信内容、頻度、費用、保存・削除、失敗時の表示を示し、利用者が明示的に許可・停止できる案。既定で外部通信しない形を優先し、必要に応じオフライン代替を検討する。実行環境の CSP・CORS 等の制約や PWA の方針は別途確認する。 |
| API キー | 作品 pack、URL、公開ログやリポジトリへ埋め込まない。第三者へ送信できるコードにキーを渡す設計を避け、保存・送信・権限範囲・失効・漏えい時の対応を先に設計する。ブラウザ内保存だけで完全な秘密保持は保証できない。 |
| ローカルサーバー／別実行環境 | OS の許可を得た別プログラム・ユーザーが起動するヘルパー等を含めて検討。**通常のブラウザ内 HTML が OS 上に任意の常駐サーバーを直接起動できると仮定しない。** 対応 OS、導入・起動・停止・削除・自動起動の同意、障害時を明示する。自動起動や「ワンボタン」も将来の設計案。 |
| アドオン的な高度機能 | 単なる色データとは別の配布物・受け口として、要求する機能ごとに表示・個別許可・拒否・取り消しを検討。管理者権限や任意コードの実行を前提にせず、必要な範囲だけに制限する。利用者が常に通常の表示・操作へ戻れるようにする。 |

ループバックのローカルサーバーも無条件に安全ではない。他サイトからのアクセス、認証・認可、CSRF・DNS rebinding 等、受信インターフェース、ポート、公開範囲、保存先、ログ、更新、停止を脅威モデルに含める。`127.0.0.1` に置けば安全という前提や、同じ端末のすべてのアプリを信頼する前提を置かない。

「公式アドオン」は検討上の呼び名。**公式・台帳 ID 一致だけでは配布内容の真正性、権限の安全性や作者を証明しない。** 配布元、更新・失効、レビューと署名／ハッシュなどの認証方法、権限範囲と取り消しを決めるまでは、信頼された実行権限を自動で与えない。

## 4. PWA と協議する受け口の最低限の論点

1. **導入前に分かること**：目的、機能、対象領域、容量・依存、接続先・送信内容、必要な権限、オフライン時、削除／解除、作者・出典・ライセンス、配布物の確認方法。これらは検討項目であり、現行形式のフィールドを追加したという意味ではない。
2. **利用者の選択**：作品紹介の閲覧、ダウンロード、インストール、権限許可、適用、外部起動を分ける。明示的な許可、機能ごとの拒否・取り消し・停止、失敗時の復旧と通常表示を検討する。作品を開いただけで起動・通信・追加許可しない。
3. **互換と分離**：旧 PWA や未対応環境では理由を表示し、追加機能を実行しない。未知の値を安全に扱い、既存設定・バックアップや他の作品を壊さない。未知の executable・CSS・URL を現行 importer へ勝手に渡さない。PWA と別実行環境の実装責任・権限境界を決める。
4. **審査と更新**：作者・内容を認証する方法、依存ライブラリとサプライチェーン、権限拡大を伴う更新の再同意、脆弱性・配布停止・失効・ロールバックを定める。権限付与前の脅威モデリングと独立レビューを行う。
5. **体験とアクセシビリティ**：許可画面、現在の権限・通信先、停止・アンインストール、データとキーの扱いを読みやすくし、キーボード・支援技術・実機・オフライン・失敗を確認。アクセシビリティ・安全な解除を作品の表現によって失わない。

PWA 側には、まず紹介だけで参照する経路と、既存のデータスキンとの違い・将来の協議窓口を相談する。新たな権限・形式・サーバー・実行環境の導入やスケジュールを今回確定しない。
