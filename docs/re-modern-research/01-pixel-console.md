# 第１案：ピクセル・コンソール — 調査・設計草案

調査日：2026-11-06 ／ 状態：**人による検討待ち。作品の登録・制作・公開はしていない。**

## ひとことで

> **ドットの秩序は残し、読むための文字は犠牲にしない。**

既存 `pixel-8bit` の「暗い画面、絞った色、四角い造形」を出発点にする。ただし、特定のゲーム機・ゲーム画面を復刻したとは言わない。小さな文字まで粗くしたり、ブラウン管のちらつきを常時再現したりするのではなく、**静かな暗色の地に、ドット書体の短い見出しと、点在する角形のアクセント**で、電子的なリズムを作る。

呼び名「ピクセル・コンソール」と仮 ID `trk-re-modern-pixel-console` は議論用であり、採用・登録済みではない。レトロな見た目と実際の「8ビット機」の仕様は別物なので、仮名にも「8-bit」を使わない。書体の元になった16×16という数値も、画面全体が16ピクセル単位で描かれるという意味ではない。

**この案はまだ完成していない。** 特に、PWA上での書体の限定適用とノーツの形は、スキンの値だけでは実現を保証できない。両方を先に解決しないまま「見出しだけドット書体」「色に頼らずプレイ可能」と売り出さない。

## 1. なぜ既存作をリメイクするか

このリポジトリの [元の目録](../../catalog/skins.json) と [巻別データ](../../skin-volumes/glitch/items/pixel-8bit.json) を確認した。`pixel-8bit` は、舞台 `#2a2a2a`、背景 `#1a1a1a`、文字 `#ffffff`、補足 `#555555`、ドン赤 `#ff0000`、カッ緑 `#00ff00`、両ノーツ `square`。書体名は Press Start 2P、動画フィルタも指定されている。

- 魅力として引き継ぎたい：限られた色、暗い舞台、角形の反復、電子的な印象。
- 改めたい：赤と緑だけに頼らない識別、長文への書体の使い分け、補足文字の読みやすさ、装飾とゲーム表示の競合。
- 差別化する点：既存パック「ドットの電子音」にも緑と黒、走査線、DotGothic がある。こちらは**走査線・発光・点滅を主役にせず**、暖色と青の二種の記号、文字を載せる落ち着いた面を軸にする。それでも画面を見比べた上で独自性を判断する必要がある。
- 既存作やその ID は変更しない。元作の制作意図や実際に全利用者が見る姿を、目録の値だけから断定しない。

### 「元の補足色は読めない」と言い切れるか

不透明単色同士の相対輝度比は `#555555` 対 `#1a1a1a` が **2.335:1**、対 `#2a2a2a` が **1.925:1**。これは元データの懸念であり、各色が実画面でその組み合わせで使われることの証明ではない。

固定した trk-PWA `f7b1272547f712d9a7d7a198404148457e936008` のインポーターに、調査時の目録を一時出力として渡すと、`pixel-8bit` の補足色は `#555555` から **`#cccccc`** に変換された。`#cccccc` 対 `#1a1a1a` の単色比は **10.838:1**。同PWAの色検査でこの既存スキンに問題は列挙されなかった。したがって「カタログ上の懸念」と「PWA生成後の値」は区別する。いずれも実画面・重なり・文字サイズを含む WCAG 合否ではない。

目録内のフォント名にはバックスラッシュがあるが、固定PWAのインポーターは `font` と `type.title` を正規化する。バックスラッシュだけを根拠に表示不具合とは断定できない。書体が利用環境に実在・ロードされるかは別の問題。

## 2. 造形の設計案

### 2.1 面と色：明るく光らせるより、読める暗さを作る

以下は**比較用の仮色**であり、目視・実機レビュー前の確定色ではない。意味は近似色に持たせつつ、ゲームの二種類は色以外でも区別する方向を目指す。

| 役割 | 仮色 | ねらい |
|---|---|---|
| 背景・舞台 | `#10151a` | 真っ黒一色を避けた、少し青みのある暗色 |
| パネル | `#172229` | 背景との段差。文字の背後は落ち着かせる |
| 入力欄／ボタン | `#101b20`／`#293c3d` | 入力と押せる面に違いをつける。境界は別途検証 |
| 本文／補足 | `#ecf6ee`／`#b8c9bd` | 白飛びを抑えつつ、補足にも十分な明度を確保する意図 |
| アクセント／その上の文字 | `#56d994`／`#092016` | 緑は操作のアクセントに限定し、べた塗りの上の文字を暗くする |
| ドン／カッの提案色 | `#ff8069`／`#69b8ff` | 旧作の赤・緑から暖色・青に変更。ただし色だけでは区別しない |
| 縁／判定など | `#8ea4aa`／`#f7d680` | 細部の境界／成功系の候補。意味と実際の隣接面は要確認 |

色比の予備計算は sRGB の各成分を線形化し、相対輝度 `L = 0.2126R + 0.7152G + 0.0722B`、比 `(明るいL + 0.05)/(暗いL + 0.05)` とした。すべて不透明単色同士、小数第3位に丸めた値。

| 組み合わせ | 比 |
|---|---:|
| 本文／パネル | 14.634:1 |
| 補足／パネル | 9.349:1 |
| 暗い文字／アクセント | 9.553:1 |
| ドン色／舞台 | 7.467:1 |
| カッ色／舞台 | 8.653:1 |

これは選んだ数組の計算にすぎない。UIの枠・状態・フォーカス、半透明面、背景画像、映像・拡大・forced colors などは別途確認が必要。色比が高いことだけでは見分けやすさも WCAG 適合も保証できない。

### 2.2 透き通りと装飾

- **提案**：文字の背後は読みやすい落ち着いた面とし、背景が変動するガラス風の大きな透過・ぼかしは使わない。飾りは細い角形や離散した小さな矩形を少量、静止状態で置く。模様は意味・境界・状態の唯一の手がかりにしない。
- ただし固定PWAの試験変換では、目録のパネル色 `#172229` は **`rgba(23,34,41,0.96)`** となる。完全不透明が実現すると仮定しない。背後による合成色を実表示で検証し、不十分なら PWA 側と不透明化や共通UIを協議する。
- 走査線、画面全体の点滅、ゆがみ、連続する発光をこの案の必須要素にしない。アクセントの変化は必要な状態表示を妨げない範囲で、静止を基本にする。将来動きを加えるなら reduced motion、停止手段、点滅の閾値を個別に検証する。**スキン装飾を静止にすることは、アプリ全体・動画・ゲーム効果の安全性を証明しない。**

### 2.3 形：色覚の違いに配慮したいが、今のスキンだけでは約束できない

仮データではドンを `square`、カッを `diamond` とした。PWA描画コードには四角・ひし形があるが、四角は角が少し丸められ、モードによって描画も異なる。小さなノーツや高速時に見分けられるかは未検証。W3C の Use of Color は、色情報に形や文字など別の視覚的手がかりを添える考え方を示すが、形を２種書くだけで適合が証明されるわけではない。

**重要な実装上の制約**：固定PWAでは実際のノーツ色と形は `settings.notes` の共通設定から取得され、UIにも「ノーツの見た目（全スキン共通）」とある。したがって、目録や生成物に `shapes` が残っても、**通常のスキン選択によって仮の二形状が自動適用されるとは言えない**。利用者の設定を勝手に上書きするのも避ける。

**追記：同じ固定版の調査で、既存の「スキンのおすすめ」ボタンを確認した。** 明示的に押すと、現在のスキンの色と `shapes` を共通ノーツ設定に保存する。一時コピーの Chromium 試験では、仮案を選んだだけではノーツは変わらず、ボタンで仮案の色・形に変わり、再起動後や別スキンへの切替後も残った。**切替で元の設定に自動復元されるものではない**。以前はこの既存ボタンへの言及が不足していた。利用者が元の設定を残して手動で戻す案内など、安全な戻し方の設計が必要。詳細は [方向性の決定記録](02-pixel-console-direction.md) を参照。画像ノーツや他のモードでも確認する。

## 3. 書体：ドットの雰囲気と本文の可読性を両立できるか

### 候補と根拠

第一候補は **DotGothic16 Regular 400**。作者 Fontworks の説明では、16×16ゴシックのビットマップをベースに、昔のゲーム・携帯・パソコン画面の雰囲気を持つ書体である。日本語の短い見出しにドットの個性を与えやすい一方、本文は `system-ui` を中心とした読みやすい書体とし、読み込み失敗時も自然にフォールバックさせたい。

これは作者の説明を踏まえた設計上の仮説であって、16pxの格子への完全な整列、小さい文字の可読性、すべての字種や端末での表示を保証しない。書体を大きくした200%表示、長い見出し、文字の欠落・フォールバックによる混植やレイアウトのずれを実際に調べる。本文を `system-ui` にしても、日本語を含む各言語でどの書体になるかは環境次第である。

旧作指定の **Press Start 2P** も調査した。作者は1980年代のゲームに使われた書体を基にしたと説明している。こちらも OFL 1.1 であるが、実際に配布するファイルのライセンス・字種を確認する必要がある。旧作の名前を引き継ぐだけで歴史的再現を主張できるわけではなく、日本語見出しとの一貫性を重視して今回は DotGothic16 を優先候補とする。

### 既存パックの実測と出典リンクの問題

[既存の DotGothic パック](../../font-packs/dotgothic.stpack) を ZIP として読み、同梱の `fonts/DotGothic16-Regular.woff2` は **396,312 bytes**、SHA-256 `a042e37d1a36798f5a9dee9ab81d2fc4204950ae1729b856e4d22833a61997ee`、パック全体は **403,433 bytes**、SHA-256 `fb06c427232cdba238ff7806d79a410b9630e582e74ee5ce8473a78cc7cc6860` と確認した。パックには OFL 1.1 の全文と著作権表示が同梱される。

一方、[SOURCE.json](../../font-packs/dotgothic/SOURCE.json)、[NOTICE.md](../../font-packs/dotgothic/NOTICE.md)、実パック内 NOTICE の上流リンク `github.com/lastrites-net/dotgothic` は調査時に 404 だった。作者の上流は [fontworks-fonts/DotGothic16](https://github.com/fontworks-fonts/DotGothic16/tree/14517183ab2f75e8bccafc5a0bff6685d268c687) で、同梱 OFL の著作権表示にもその上流が記載されている。**404 は OFL 違反や書体の不正を証明しない**が、出典をたどれないまま新作の根拠にはできない。新規配布前に、出典リンクを訂正し、ソース、実パック、生成目録・リリースの整合を取り、実際のファイルに適用される表示・同梱条件を確認する。本調査では既存パックを変更していない。法的助言ではない。

この既存 WOFF2 の `cmap` を [検査ツール](../../tools/check-fonts.mjs) で読み、単独コードポイントの一部を確認した（収録 6,884 コードポイント）。`A`、`0`、`あ`、`ア`、`漢`、`龍`、`中`、`好` は収録、`你`、`한`、`글`、`❤`、`🎵` は未収録だった。**日本語サブセットであり、中国語・韓国語にも全面対応とは言えない。** `cmap` は対応する文字の一部を見るだけで、表示品質、字形の適切さ、異体字・結合文字・全言語の網羅を保証しない。上流 TTF の収録字種とこの WOFF2 は同一とは限らず、Google Fonts の上流 commit が本パックのバージョン同一性を証明するわけでもない。

### PWA連携の障壁

固定PWAの `core.applySkin` は通常書体の `--font` と見出し用 `--font-title` を別に扱う。一方、書体パックのロード済み書体は `--font` の先頭に置かれる。書体だけのパックでは現在のスキンに適用され、スキン付きパックではそのパックのスキン使用時に限定される。**既存 DotGothic パックはスキン付き**なので、それを有効化して別の通常スキンへ切り替えれば、新案の見出しだけに DotGothic が残るとは考えられない。加えて、書体パックが `--font` に入る方式は、本文にも及びうる。

仮データの `type.title` は `"TrkDotGothic",monospace` と書体名を指定しているだけで、書体の供給・見出しだけへの適用を保証しない。フォントのみパックの方式、独立した書体アセットの提供、PWA 側の限定読み込みなどを比較し、権利情報・失敗時・切替・解除・復元を含めて PWA 側と検証する。利用者が明示的に設定した書体や読みやすさの設定を上書きしないことも条件。

## 4. 一時的な PWA 色実験

[研究用仮データ](pixel-console-candidate.json) と [再実行スクリプト](../../tools/research-re-modern-pixel.mjs) を用意した。これは**正本、公開スキン、完成品ではない**。既存目録の `pixel-8bit` を一時コピーし、仮値を上書き。試験のためにだけ仮 ID を既存の `glitch` グループに加えて PWA インポーターで一時出力した。ラベルと説明は旧作のものを試験用に継承しており、新案の完成した翻訳ではない。`glitch` 所属も本採用の提案ではない。

2026-11-06 の実行結果：

- 使用した目録 SHA-256 `b4698e136b120ed8ca4a1bd348a102ed5f03b5efecbcb701980886fb11311db7`、PWA commit `f7b1272547f712d9a7d7a198404148457e936008`。
- 生成 177 種（既存 176 種＋仮案）。仮案の checker 問題 **0**、holdback 宣言・holdback 問題とも **なし**。対象ファイル全体では通常問題 0、別件の既知 holdback は 11 組残っている。
- 仮の本文・補足・アクセント色は上記の値で生成され、パネルは前述の `rgba(...,0.96)`。インポーターの仮案についての色調整通知はなかった。
- この検査が確認するのは生成データ上の所定の色の組み合わせだけ。画面を開いていない。フォントのロード、ゲーム中の形、ユーザー設定、同化・多言語・カテゴリー画面、フォーカス、動き、利用者による判断は検査していない。全体の `ok` は既知 holdback を除外するので、全スキン全色が合格という意味ではない。

未変更の固定PWA checkout が必要。研究時の目録 SHA と一致すればそのまま使う。今回の概念整理だけをマージする際に、他の未マージ配色変更を含めないため、目録が研究前の基準 SHA `8f1e9fa713c1b2c62567fba074f1c3cf245eac4e02d94f6aa515c74b683727e7` に一致する場合は、[研究用の履歴差分](pixel-console-catalog.patch)を**一時コピーだけに**適用し、記録された SHA と一致することを検証する。どちらでもない場合は止まる。この差分は実験データの復元用であり、配色変更の採用・公開を意味しない。一時ファイルは終了時に削除する。

```sh
TRK_PWA=/path/to/clean-trk-pwa node tools/research-re-modern-pixel.mjs
```

`/path/to/clean-trk-pwa` は利用者の環境にある checkout のパスに置き換える。仮データを変更して再実行する際は、この文書の記録は過去の結果として扱い、結果を新たに記録する。

## 6. 制作・登録に進む前の検証

1. 方向性を人がレビューする。既存 `pixel-8bit` と「ドットの電子音」を、静止画だけでなく通常画面・設定画面・ゲーム画面で並べず個別に見比べ、似すぎ・装飾不足・暗さ・個性を評価する。
2. 正しい書体出典の確定、既存ソース／NOTICE／実パック／目録／リリースの整合、OFL 条件の確認と修正方針を決める。実験した WOFF2 のバージョン・生成経路も追跡する。
3. PWA と書体の読み込み範囲およびノーツの共通設定との関係を協議。提案した「見出しだけ」「二形状」「戻せる」の実装手段と失敗時の代替を決める。ユーザーの変更を勝手に上書きしない。
4. 配色の合成後を Chromium などで測り、通常／hover／選択／無効／フォーカス、境界・非文字、背景動画、200%文字拡大、狭い画面、forced colors、reduced motion を確認する。Chromium の確認は他ブラウザや実機、人間の判断の代わりではない。
5. 日本語・英語・中国語・韓国語の実画面と、書体なし・字形なし・遅延・切替後のフォールバックを確認。既存サブセットの全字種を推測しない。
6. ノーツ画像・レイアウト・プレイ速度・利用者が設定を変えた場合を確認し、色覚多様性への配慮を実際の形と説明でレビューする。アクセシビリティや安全性を根拠なく保証しない。
7. 採用が決まってから [カテゴリーのガイド](../trk-re-modern-guidelines.md) に沿って、作品の記録・レビュー・公開詳細・台帳・生成物を作り、機械検査と人手レビューを行う。
