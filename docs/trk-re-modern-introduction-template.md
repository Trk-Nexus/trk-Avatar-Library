# trk-re-modern：個別作品紹介・カタログ書式 v1.1

2026-11-07：依頼者の方針に沿い、公開向けの読み物と制作中のメモの扱いを追記。JSON 形式・登録ゲートは変更しない。

これは [コンセプト・制作方式](trk-re-modern-concept.md) と [制作・調査・公開ガイドライン](trk-re-modern-guidelines.md) に沿って作品を説明するための**共通書式**。研究用草案でも使えるが、これを埋めるだけでは正本登録・ライセンス確認・公開・人的レビューは完了しない。記入できない箇所は推測で埋めず「未確認／未実施」と書く。**候補・構想・実装済み・検証済みを混ぜない。**

実際の読者向け詳細は `gallery/re-modern/<ID>.html`、作品間を探す一覧と検索は `gallery/re-modern/index.html`、制作・検証は `docs/re-modern/<ID>.md`、構造記録は `catalog/re-modern/records/<ID>.json` に置く。正本登録時の正確な要件はガイドライン §8 と検査ツールに従う。空の研究用書式や架空の作品を登録・公開物に入れない。

## 読み物と制作メモを分ける

作品の「裏面」は、概念を伝える**公開向けの読み物**と、その根拠や開発の流れを追うための**制作メモ・検証記録**をつなぐ考え方。必ず物理的なカード裏面や回転アニメーションを実装する意味ではない。既存の作品詳細ページの構成としても扱える。切替見本や PWA の機能は別途設計・合意し、未実装ならそう示す。

### 公開向けの読み物

- 読者が辿りやすい文章で、概念、対象場面、着想・歴史的背景や図柄、書体・構図・色などの候補と選択理由、残したこと・変えたことを説明する。資料の事実と作者側の解釈、仮説を区別し、未確認は未確認と書く。
- 実際の選択肢・見本・作品の状態を示し、検討しただけの候補を実際に適用・切替できるように見せない。候補すべての実装や配布を義務づけない。
- 引用・図版・素材の権利を個別に確認し、読者が参照できる出典・一次資料や公開できる検証記録への導線を用意する。外部リンクは閲覧先とし、出典表記だけで画像等の再配布が許されるとは扱わない。
- PWA や公開ページに表裏の操作を設ける場合は、キーボード・読み上げ・フォーカス・拡大・狭い画面・動きの軽減に配慮し、回転演出なしでも読める方法を検討する。JavaScript が使えないときも一覧と詳細から読み物と出典に到達できるようにする。

### 制作メモ・検証記録

- 作業中は整った文章を待たず、断片や保留も残してよい。記録できる範囲で **日付／問い／調査先・版／観察／候補／判断と理由／未確認・次の作業** を添える。判断が変われば理由を追記し、古いメモを現在の判断と混同しない。記録がないことを推測で埋めない。
- 公開前に、採用する文章の出典、歴史的事実と解釈、権利、検査結果、現在の実装状態を照合する。未整理メモをそのまま読者向けの完成文として扱わない。公開後の変更も作品詳細と検証記録で追跡できるようにする。
- **保存場所と公開範囲は別。** GitHub リポジトリや共有 Drive は、作品ページにリンクしていなくても閲覧できる場合がある。「開発メモ」と書くだけで非公開になるわけではない。個人情報、未公開のやり取り、認証情報、許可のない資料などは公開リポジトリや共有フォルダに入れず、権限に合った場所で扱う。読者向けのリンクは公開可能な資料・記録に限る。
- 既存の正式登録では `docs/re-modern/<ID>.md` の検証記録も必要。作業メモの追加はその代替ではなく、公開ゲート・権利確認・独立レビューも省略しない。形式やファイルを増やすこと自体を新たな機械ゲートにはしない。

読み物とメモを一緒に検討した研究用の[ピクセル・コンソール文章見本](re-modern-research/05-concept-reverse-pixel-console-draft.md)を参照。作品は依頼者に承認済みだが、文章見本・切替機能の公開や作品の正式登録を意味しない。

## 一覧に出す最小情報

- **作品名／状態**：構想・検証中・公開済み・差し戻し・更新の区別。作品IDは決定時に記載。
- **一文のコンセプト**：何を体験してほしいか。旧作のリメイクなら元IDと差分に辿れること。
- **対象領域と実装状態**：共通UI・書斎・基地・ゲーム等を列挙し、それぞれ「見本のみ／提案／実装／未対応」を区別。書斎・基地の切り替えを勝手に「対応済み」と書かない。
- **書体の要約**：見本・実装済みの実際の書体と候補を別欄にする。システム書体は総称とし、具体的なフォントが表示される保証をしない。
- **詳細へのリンク**：理由・条件・出典・戻し方・未検証に到達できること。適用やダウンロードを装う動かない操作は置かない。
- **検索**：作品名・別名・コンセプト・対象領域・書体名を候補か採用済みかを区別して検索できること。検索文字列を追跡・外部送信・保存しない方針を示し、JavaScript 無効時も一覧と詳細を読めるようにする。検索による文字種・濁点などの扱いと未確認を記録する。

## 詳細ページの共通項目

### 1. 概要・状態

作品名、ID、作品／記録の版、作成・更新日、現在の状態、対象環境、見本と実動作の差、既存スキン・参考との関係。作者・権利者・ガイドの提供元を混同しない。見本・構想・既存機能・将来の提案を視覚的にも区別する。

### 2. コンセプトと選択の理由

対象シーン、一文の意図、デザインの柱、選択しなかった案、トレードオフ。既存作から何を残し、何を変え、何を再現していないか。作品固有の表現と引用・参考を分ける。

### 3. 対象領域ごとの設計と互換性

| 領域 | 理由・役割 | 実装状態 | 利用者設定との関係／戻し方 | PWA・旧版の制約・未確認 |
|---|---|---|---|---|
| 共通UI | 作品ごとに記載 | 見本／構想／実装等 | 既定・優先順位・解除 | 受け口と適用範囲 |
| 書斎 | 適用しない場合もその旨 | 同上 | 本文テーマ・サイズ・余白を尊重 | 実装有無と合意状況 |
| 基地 | 適用しない場合もその旨 | 同上 | 再生・字幕・映像との関係 | 実装有無と合意状況 |
| ゲーム等 | 作品ごとに記載 | 同上 | ノーツ・表示・解除 | 適用条件・未確認 |

この表はPWAに新たな設定があるという宣言ではない。新しい受け口・データ形式・初期値は受け手との合意が必要。異なる領域の設定を一つのスキン選択で勝手に上書きしない。

### 4. 色・面・透明・動き

役割ごとの色と背景・重なり、透過率、静止／動き、減速や停止、fallback、前提条件。候補と実装値を区別する。コントラストの計算は組み合わせ・合成方法・環境を示し、数値だけで実画面・全作品の適合としない。安全な操作面・強制色・フォーカスを説明する。

### 5. 書体カード：用途ごとに記録

**見本、作品の実装済み、候補**を別カードにし、見出し・本文・英数字・ゲーム表示・書斎・基地など適用場所を示す。該当なしは省略せず理由を書く。

| 項目 | 記入する内容 |
|---|---|
| 状態と用途 | 見本で実使用／作品で実使用／候補／未採用。見出し、本文など |
| 正式名称とファミリー | 例：書体正式名と、アプリで登録する内部family名を区別。system系は端末依存と明記 |
| ウェイトと形式 | 400等、ファイル形式、可変書体なら範囲。system系の解決先や太さは環境依存と明記 |
| 選んだ理由 | 読みやすさ・世界観・優先したことと、まだ検証していないこと |
| 作者・出典 | 作者／権利者、一次資料の題名・URL・版・確認日。システム書体で不定なら理由 |
| 入手先・版・容量 | 実ファイルの配布元・バージョン・バイト数・SHA-256。同梱しない場合はその旨 |
| ライセンスと条件 | ライセンス名・全文の場所・表示・再配布条件・未確認事項。URLだけでは許諾にならない |
| 字種と代替 | subset、実測の範囲、欠字やロード失敗時の fallback、異なる端末・言語での不確実性 |
| 利用・解除 | 既存の書体カタログ／パックへの到達方法、同パックが変えるスキン・ノーツ等の副作用、適用範囲と戻し方。未実装なら未実装と書く |

具体的なフォントへのリンクは、作品にすでに適用できることを意味しない。PWAの書体パックの同時適用・設定変更・復元は作品ごとに確認する。外部サイトへの移動と書体の取得・適用は別の操作として示す。

### 6. 利用条件・安全性

対応・未対応・未検証の環境、容量、動作時通信、権限、データ保存、失敗時の代替、注意、選択・中止・解除・復元。強制色・文字拡大・reduced motion・背景動画などに関する現状を書く。安全な解除がない場合は未対応として差し戻す。

### 7. 確認・変更履歴

調査日・参照版・検査環境、機械検査の対象と結果、手動／実機／当事者の評価、失敗・保留と残課題、別の人のレビュー者・日付・判断・証拠。更新時は、旧版、何を変更しなぜ変更したか、対象領域・色・書体・設定・互換・解除への影響、再検証と残るリスクを追記する。未実施を完了扱いにしない。

### 8. 出典と関連記事

作品の着想元、ガイドの固定commit、実際の素材の上流・ライセンス・取得元を、タイトル・URL・確認日・参照した内容で列挙する。書体カタログ、既存作品、必要な検証記録へリンクし、検索・一覧から到達可能にする。

## 書式と機械ゲートの関係

本書式は人が使う読者向け構成とレビュー項目であり、現行 `check-re-modern.mjs` のJSON形を勝手に変更しない。現行の `typography` は1組の構造欄なので、複数の用途や候補は詳細ページ・検証記録で区別して記載する。機械的に複数書体・領域別状態を強制する必要が生じた場合は、互換・既存作品の移行・テスト・公開パイプラインを同時に設計し、ガイドライン §9 に従って別途更新する。
