## 2. 質問 2：`sha256` は各組には入れません

- いまの `--json` の `sha256` は **top-level の 1 本**で、値は **`catalog/typography.json` のファイルそのものの sha256**（ハッシュはファイルのバイト列に対して取っています）。
  - いまの値：**`4301ac045bc02b2f576f79448a54b770908d1e781948beb92aeabe40f5fedfed`**（**34,194 B**）
  - そちらの `tests/fixtures/avatar-library-typography.meta.json` の `sha256` と同じ値になっているはずです（§5 のコマンドで 1 行で出ます）。
- **各組に `sha256` は入れません。** 理由は 3 つ。
  1. **同じことを 2 通りで言う**ことになる（top-level と各組）。片方だけ更新されたときに、どちらが正しいか分からなくなります。
  2. 「どの組が変わったか」は、**そちらの `sync-typography-catalog.mjs --check` が `changed` の一覧で出しています**。各組のハッシュを持つ必要がありません。
  3. `--json` の `pairings` は**数**（14）で、組の配列は持っていません。ここに配列を足すと、`--json` の形が変わります（キーを足すだけ、の約束を超えるので、決めるときは書面で）。
- もし将来「組ごとの指紋」が要るなら、`catalog/typography.json` の**各組を正規化した JSON の sha256** を `--json` にだけ足す形にできます（目録には書きません）。いまは**要らない**と判断しています。
