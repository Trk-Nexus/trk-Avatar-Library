## 2. Q1〜Q5 の返事（全部 ○ です）

### Q1. 拡張子は `.stlib` で合っていますか → **はい。`.zip` も受け付ける方針に賛成です**

こちらも **`.zip` と `.stlib` の両方**を配ります（中身は同じ・**バイト列も sha256 も同じ**）。
`.stlib` は「ZIP をそのまま `.stlib` に改名しただけ」です（無圧縮・決定的）。理由は、
- trk235 より前のアプリの人でも、`.zip` を展開して「📥 まとめて入れる」で入れられる
- OS によっては `.stlib` をダブルクリックで開けない（関連付けが無い）ため、逃げ道を残す

### Q2. 中身のパスは `catalog/index.json` ＋ `packs/…` で合っていますか → **ほぼ合っています。ただし 2 つのフォルダです**

実際の中身（r4・21 ファイル）はこうです。

```
README-はじめに.txt        … 説明（UTF-8・任意のもの）
set.json                   … セットの名前と版（§3・任意）
gallery/all-skins.html     … 全スキンの見本（アプリは読まない）
gallery/fonts.html         … 書体の一覧と検索（アプリは読まない）
catalog/index.json         … 目録（version 1・`build-catalog` の出力そのまま）
packs/sample-mincho.stpack … 目録の packs[].file と同じパス
font-packs/*.stpack ×15    … 同上（書体パックは `packs/` ではなく `font-packs/`）
```

- **`packs/` だけではありません。書体パックは `font-packs/` にあります**（目録の `packs[].file` がそうなっているため）。
  「目録の `packs[].file` と同じパス」という規則で読んでもらえれば、こちらはこれ以上増やしません。
- `gallery/` の 2 枚は**ブラウザで見る見本**で、アプリに入れるものではありません（目録にも載っていません）。
- パスはすべて安全な相対パス（`..`・先頭 `/`・バックスラッシュ・制御文字なし）です。

## 3. はじめてセットが 30.8 MB になった件（重さの相談）

こちらでの結論は **「一括で配るものは一括のまま。ただし“1 本だけ”の導線を必ず用意する」** です。

- **はじめてセット（r4）は全部入りのまま**：見本 2 枚＋目録＋16 パックで **30,832,151 B（29.4 MiB）**。
  「収集してまとめたものを一括で公開する」という倉庫の役割はこちらが持ちます（ミュージアムのように、まず全部を並べる）。
- **1 本ずつは `gallery/fonts.html` から**：行ごとの「⬇ .stpack」で、その 1 本だけ落とせます。
  目録＋その 1 本で入るので、**はじめての人がいきなり 29 MB を落とさなくても済みます**（§4）。
- **(b) 書体セットを別に配る案・(c) 2 つとも配る案は、まだ決めていません**。
  いまのところ (a) 全部入り＋個別導線で足りていますが、書体が **+10〜14 種（25〜35 MB）** 増えると
  はじめてセットが **60 MB 前後**になる見込みなので、そのときは **(b) か (c) に切り替える**つもりです。
  切り替えるときは、こちらから先に相談します（**100 MB 未満**は守ります）。
- なお、セットは**展開して「📥 まとめて入れる」**なので、どちらの形でもアプリ側の扱いは同じです。
