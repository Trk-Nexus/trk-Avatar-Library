## 4. 設定の細分化（4 段階）

アプリの今の設定は、スキンの `font` **1 つ**です（`sanitizeSkinDef` が `font` を 1 つ返し、画面の全部がそれを使う）。
これをいきなり 6 役にすると、利用者は「どれを変えればいいか」が分からなくなります。**段階**にしました。

| 段階 | 設定の形 | 何が変わるか |
| --- | --- | --- |
| ① `one`（いま） | `skin.font` 1 つ | 何も変わらない。**この段階は残す** |
| ② `pair` | `display`（見出し用）＋ `body`（本文用） | 見出しと本文を分ける。**いちばん効く**（記事の定番） |
| ③ `roles` | 5 役（題字・見出し・本文・注記・差し色） | 役ごとに family・太さ・倍率・字間・行間 |
| ④ `digits` | ③＋`numeral` | スコアの数字だけ別書体（桁が揃う） |

大きさは**倍率だけで決める**（本文＝1、注記＝`1/倍率`、見出し＝`倍率`、題字＝`倍率³`）。倍率は 1.125／1.2／1.25／1.333／1.5 の 5 種。
こうすると、役を増やしても「本文との関係」が保たれ、スキンごとに数字を手で直さなくて済みます。

字間・行間は**範囲つきの既定値**にしました（例：本文の行間 1.8・許す範囲 1.6〜2.1）。自由入力にすると必ず崩れるためです。

## 6. アプリ側へのお願い（案・まだ決めていません）

**足すだけ**で、古いアプリは今までどおり動く形にしています（`sanitizeSkinDef` は知らない項目を捨てるだけ）。

```jsonc
// 利用者の設定（settings.typography・任意）
// パックが提案するときは pack.json の skin.typography に同じ形で書く（任意）
{
  "format": "trk-typography",
  "version": 1,
  "pairing": "shinbun",          // どの組から始めたか（表示用・無くてもよい）
  "base": 16,                     // 本文の大きさ（px）
  "scale": "1.25",                // 倍率（1.125 / 1.2 / 1.25 / 1.333 / 1.5）
  "slots": {
    "display": { "pack": "font-packs/noto-serif-jp.stpack", "family": "TrkNotoSerifJP", "weight": 700, "size": 1.953, "tracking": 0.0,  "leading": 1.1 },
    "heading": { ... },
    "body":    { ... },
    "caption": { ... },
    "numeral": { ... },          // 任意（④ の段階）
    "accent":  { ... }           // 任意（③ の段階）
  }
}
```

- 書体は **`family`＋`weight`** で指す（`pack` は「どのパックに入っているか」の覚え書き。無くても動く）
- `size` は**本文を 1 とした倍率**（px ではない）。倍率を変えたら全役が一緒に動く
- `slots` に無い役は `skin.font`（①）に落ちる。だから**部分的にだけ**細分化しても壊れない
- 画面のどこに当てるかは、アプリの描画（`core.fontFamily()` の呼び出し 20 か所）を役に振り分ける作業が要ります。**こちらでは決められません**（§7）

## 7. こちらで決めなかったこと（trk-PWA 側の判断）

1. **役の数をどこまで出すか**（② で止めるか ③④ まで出すか）。この倉庫は 4 段階ぶんのデータと見本を用意しただけです
2. **描画のどこをどの役にするか**（`ctx.font` を触っている 20 か所の振り分け）。`render.js` の判定文字は `display`、曲名は `heading`、設定の説明は `body`、キー表示は `caption`、スコアは `numeral`、`PERFECT` は `accent`、という**案**までは書けますが、実際の見え方は実機でしか決められません
3. **`pack.json` に `skin.typography` を書くか**。書くと「パックが組み合わせを提案する」ことになります。書式は §6 の案で、**先に書面で合意してから**にしたい（共有の契約なので）
4. **設定画面の UI**（スライダーか選択か・プレビューをどこに出すか）。試作の操作感は `gallery/pairings.html` を見て決めてください
