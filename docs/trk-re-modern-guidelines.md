# trk-re-modern 制作・調査・公開ガイドライン v1

**適用：trk-re-modern の全作品。** 美学・機能・実験のいずれを優先しても、下記の必須事項は省略しません。これは制作側の決まりであり、既存スキンの一括変更や、PWA 側の未合意の仕様追加を意味しません。研究用のリメイク案はありますが、正式登録作品はまだありません。カテゴリーの考え方と制作方式は [コンセプト文書](trk-re-modern-concept.md)、紹介の記入方法は [共通書式](trk-re-modern-introduction-template.md) を参照してください。

## 1. 目的と方向

個性のある見た目を作るだけでなく、**なぜそう作ったか、何を参考にしたか、どこまで確かめたかを辿れる作品集**にします。

- **美学特化**：配色、光、質感、透明感、書体、世界観を追求する。
- **機能特化**：集中、操作、情報の階層、用途に応じた機能を追求する。
- **実験・表現特化**：目的を説明したうえで、尖った表現や技術を試す。

併用可。どれが優れているという序列ではなく、意図とトレードオフを明記します。美学優先は作品の見た目の選択であって、利用者への警告、操作、解除の安全を省く許可ではありません。

## 2. 出発点：適用する資料

制作前に [Modern Web Guidance source](https://github.com/GoogleChrome/modern-web-guidance-src) の該当ガイドを検索・確認し、使用した版と根拠を作品記録に残します。内容は更新されるため制作時に再確認します。現在の基準参照は `690d58e799bc74e2740880d84a01625e8746eaff`：

- [Color](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/visual-design/color/guide.md)：文字や操作のコントラスト、色以外での状態表示、強制色。
- [Motion](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/ui-behaviors/motion/guide.md)：動きの軽減、停止、点滅への配慮。
- [Accessibility](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/accessibility/accessibility/guide.md)：標準的操作、名前・状態、支援技術と当事者を含む検証。
- [Typography](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/visual-design/typography/guide.md) と [font fallbacks](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/visual-design/visually-stable-font-fallbacks/guide.md)：拡大、折り返し、代替書体。
- [Privacy](https://github.com/GoogleChrome/modern-web-guidance-src/blob/690d58e799bc74e2740880d84a01625e8746eaff/guides/privacy/privacy/guide.md)：情報の最小化、利用目的、透明性。

必要な資料はこれらに限定しません。ガイドはプレビュー版で、採用は対象環境と実測に照らして判断します。参照元に記載の新 API を無条件で使う義務や、ガイドに実際には書かれていない要件を帰属させることはしません。

## 3. 調査・検索・権限の取り決め

| 対象 | 方針 |
|---|---|
| 公開資料の検索・閲覧 | **制作調査のために行ってよい。** 実行環境のアクセス制限、サイトの利用条件を守る。検索語、確認日、一次資料の URL、どの記述の根拠かを記録。検索結果の要約だけで断定せず、原典・版・著者を確かめる。確認できないものは未確認と書く。 |
| 資料や素材の取得 | 公開されていることと再配布可能であることは別。作者、配布元、ライセンス全文、改変・再配布条件、クレジット、バージョン、取得元・ハッシュを確認してから同梱する。条件が不明なら同梱しない。出典リンクを載せるだけで許諾を得たことにはならない。 |
| 調査ツールとブラウザ | 制作時の Chromium / Playwright、ブラウザ開発者ツールやローカル検査を使ってよい。利用する実環境・依存関係を明記する。**Chromium で検査したことは、利用者に Chromium が必須という意味ではない。** 実際に必須なら理由と対象バージョン・代替手段を公表し、他ブラウザの未確認を隠さない。 |
| 外部送信・ブラウザ権限 | 制作調査の検索許可は、スキン使用時のネットワーク通信や位置情報・カメラ・マイク・通知などへの許可ではない。作品は原則、使用時に追加権限や追跡を要求しない。必要な例外は目的、送信先、保存期間、拒否時の挙動を事前に示し、明示的な許可と別途レビューを必要とする。 |
| 副作用のある操作 | ソフトの導入やデータ収集は環境と権限の範囲内で実行。ログイン・課金・個人情報・外部送信・権利者への連絡・公開・第三者共有は、このガイドだけでは許可されない。別途必要な権限・承認を得る。 |

検索やソース参照は権利を生みません。利用者が閲覧できない資料、推測、AI生成の説明は事実と分け、裏取り前は根拠として確定しません。参照先の存続や真偽を自動検査が保証するわけではありません。

## 4. 各作品に必須の説明

1. **目的・方向性**：対象場面、制作意図、優先したこと、犠牲や制約、独自制作と参考にした部分。
2. **書体**：実際の書体名・太さ・作者／権利者・選定理由・入手先と版・ライセンス・配布条件。`pack` 同梱／端末の `system` 書体／`browser-default`／`original` を区別する。入手 URL がない場合は理由を記載。同名の書体が端末にある保証はない。欠字・未導入・ロード失敗時の代替、元に戻す方法も示す。`Trk...` のようなアプリ内部 family 名を元の書体名やオリジナル書体と取り違えない。
3. **視覚設計**：主要色と役割、背景・文字・操作面、透明／半透明の対象と重なり、演出、前提とする背景、代替表示。見本とアプリ実表示が異なりうる場合は区別する。
4. **出典**：Modern Web Guidance の利用した版と箇所、作品の着想源、書体や素材の一次資料、取得元・ライセンス。URL・題名・確認日・どこを参照したかを記録。オリジナルの場合はオリジナルと記載し、架空の参考資料を作らない。ガイドに触発されたことと、Google や作者による公認を区別する。
5. **利用条件**：サイズ、通信・権限、対応・未対応環境、PWA と旧版での挙動、制限、失敗時の代替。未検証は未検証と書く。
6. **評価と残課題**：検査環境・日時・方法・結果、失敗／差し戻し、未確認事項、レビュー者と判断。警告や説明は不合格の免除ではない。

説明文の詳細は人が読める作品ページへ掲載し、検索から辿れるようにします。作業記録だけを置いて公開ページから見えない状態では完了にしません。作品の一覧と個別紹介を同じ観点で作る際は [個別作品紹介・カタログ書式 v1](trk-re-modern-introduction-template.md) を参照し、特に見本で実際に使用した書体、作品で実際に使う書体、候補書体を分けて説明します。書斎・基地への展開は各領域の実装状況と利用者設定の扱いを明示し、PWAに未実装の受け口を対応済みとしません。この書式は現行JSONゲートの形式を変更するものではありません。

## 5. 表現の自由と安全に戻れる設計

- **作品の表現と操作・案内を分ける**。実験的・低可読の作品表現は明示的に選べますが、スキン選択、警告、設定、解除・戻る操作の可読性と操作性は維持します。利用前に注意を示し、勝手に適用しない。安全な既定と解除経路を用意する。対象アプリ側に実装がない場合は「対応済み」と言わず差し戻す。
- 読める案内や操作は通常文字 **4.5:1**、大文字・必要なアイコンや UI の境界／状態 **3:1** を目安に検証する。透明・グラデーション・動画など背景が変化する場合は実際の合成後・考えられる背景を検討し、色1点の比率だけで合格にしない。色だけで状態を示さない。意図的低可読の宣言は PWA の検査や差し戻しを免除しない。
- OS の強制色・高コントラスト、文字拡大を尊重し、境界・状態・フォーカス・操作が失われないようにする。美観保持だけを目的に強制色を無効化しない。スキン本来の色を確認する見本と、安全な操作面は分ける。
- 自動的に動き続ける演出は停止できること。`prefers-reduced-motion` を尊重し、動きの性質ごとに静止／軽減する。全アニメーションを一律 `0.01ms` にする方法に頼らない。点滅・閃光は発作の危険を伴うため、警告のみで正当化せず、速い点滅を避け、必要なら専門的な評価を行う。回避不能な危険表現は採用しない。
- 透明・ブラーや高負荷エフェクトは使用者が抑制でき、未対応ブラウザでも意味・操作を失わない代替を用意する。端末によって見た目や負荷が異なることを明記する。
- キーボード、タッチ、読み上げ、IME、フォーカス復帰、200%拡大、狭い画面を対象とする。意味や選択を色・動きだけに依存させない。

## 6. 実装・配布の境界

- 既存スキンを無断で上書きしない。新カテゴリーは `trk-re-modern-...` の別 ID と `trk-re-modern` タグを使う。既存作品の引用・リメイク元と変更点を明記し、旧色・旧 ID は保持する。保存状態や更新・ロールバックも評価する。
- 詳細記録は Avatar 側の別記録とし、互換性の確かめられていないプロパティを PWA 正本へ勝手に追加しない。PWA で使う表現・書体・警告・停止・解除、データ形式、既定値、旧バージョンの挙動は受け手と事前に合意・検査する。Avatar の見本だけにある機能を PWA の機能として宣伝しない。
- 素材の権利を確認し、作品・書体・画像・コード等それぞれのライセンスとクレジットを分ける。容量と依存関係を表示し、可能なら単品取得・軽量な選択肢を設ける。大きな書体や画像を全利用者に一括ダウンロードさせない。
- 参照資料や理由は検索対象にできるようにするが、検索のために閲覧履歴や検索語を外部送信しない。検索機能の通信や保存が必要になった場合は別途判断し、利用者に示す。

## 7. 検証と公開のゲート

作品追加時は、少なくとも次を**実施して記録**し、残る問題を可視化してください。

1. **機械検査**：目録、重複 ID、生成物、作品記録、権利・出典欄、PWA 固定版との互換・既存差し戻しを確認する。得られた数値の意味と対象を記す。
2. **ブラウザ**：Chromium の版・OS・検査内容・結果を記録。適用対象の Firefox・Safari・モバイルなども確認し、未実施は理由付きで明示する。Chromium での成功を全ブラウザの合格と言わない。
3. **人による確認**：書体と出典の妥当性、表現の意図、読みやすい案内、実際の解除、透明・動き、キーボード／読み上げ、文字拡大、低速・障害・オフライン、実機の見た目を確認。障害のある利用者のレビューも計画する。未実施は公開判断に含める。
4. **作品ページと検索**：説明・出典・注意・容量・対応範囲・戻し方が見つかり、一覧と検索から作品詳細へ到達できることを人が確認する。見本と実装済みの範囲を区別する。
5. **レビュー**：別の人が記録と表示・テスト証拠を照合し、承認者、日付、判断、未解決事項を残す。利用者を危険にさらす解除不能の不具合、権利不明の同梱物、PWA 側で未合意の仕様を理由付きで見逃さない。

機械検査に通っても、説明の真偽、権利、視認性、テストの実施、レビューの実在、画面の操作性やアクセシビリティを証明したことにはなりません。条件を満たせない作品は、正本や公開物に入れる前に作業案として保留します。

## 8. この決まりを忘れないための登録と自動検査

- 現時点では `catalog/re-modern/index.json` の `ids` は空。新作・リメイクはまだ追加していません。
- 正本 `catalog/skins.json` に入れる際は、ID を `trk-re-modern-` で始め、`cat` に `trk-re-modern` を含め、台帳の `ids` に同じ ID を登録します。片方だけの登録や未登録は失敗します。別名でカテゴリーを迂回してはいけません。
- ID ごとに `catalog/re-modern/records/<ID>.json`、人による検証記録 `docs/re-modern/<ID>.md`、公開詳細 `gallery/re-modern/<ID>.html` を用意。作品があるときは検索・一覧 `gallery/re-modern/index.html` も必須です。公開用ビルドは登録されたページだけを収録し、巻一覧から案内します。ページが必要とする別アセットは自動追加されないため、自己完結させるか、公開対象の設計を変更して欠けがないか確認してください。
- 作品記録には以下を文字列で具体的に記入します。`sourceUrl` は HTTPS URL または `null`（その場合 `sourceReason` 必須）。`pack` と `original` は URL 必須。参照は `guidance` / `design` / `font` / `other` に分類し、少なくともひとつは commit を固定した Modern Web Guidance の `guidance` を記載します。JSON の形の見本は [`tests/re-modern-policy.test.mjs`](../tests/re-modern-policy.test.mjs) の **架空のテストデータ**です。実在する作品や資料の証拠ではありません。

| 記録欄 | 必須内容 |
|---|---|
| `id`, `version`, `directions` | 正本と同じ ID、記録版 `1`、`aesthetic` / `functional` / `experimental` の1つ以上 |
| `concept` | `intent`, `tradeoffs`, `originality` |
| `typography` | `family`, `origin`, `sourceUrl`, `rationale`, `license`, `distribution`, `fallback`。URL 不在時 `sourceReason` |
| `design` | `palette`, `transparency`, `effects` |
| `safety` | `readability`, `exit`, `motion`, `forcedColors` |
| `permissions` | `research`, `runtimeNetwork`, `assetRights`, `browserRequirements` |
| `compatibility` | `pwa`, `legacy` |
| `verification` | `chromium`, `accessibility`, `contrast`, `failureCases`, `unverified` |
| `references` | `kind`, `title`, `url`, `checked`（YYYY-MM-DD）, `relevance` の配列 |
| `review` | `reviewer`, `date`（YYYY-MM-DD）, `approved: true`, `decision`, `evidence` |

`npm run check:re-modern` は台帳と正本の対応、必須欄・日付・URL 形式、記録と公開ページ、およびコンセプト文書と共通紹介書式のファイルの存在を検査します。書式が実際に使われたか、内容が正しいかは検査しません。`npm run check`、`npm test`、Pages 組み立て、セット公開ワークフローにも組み込んでいます。**構造上の門番**であり、内容や検索・詳細画面の品質は上記の人によるレビューが必須です。予約 ID・タグ・巻によって検出できる範囲に限られ、別名を偽装する行為や、検査の意図的な除去までは防げません。

## 9. 変更と例外

この文書を変更するときは、理由、影響する既存作品、検査、移行方法をレビューし、文書とゲートを同時に更新する。例外が必要な場合は理由・期間・影響・責任者・代替策を記録し、事前承認を得る。危険な操作や権利未確認を自動的に許す例外は設けません。PWA 側の未合意仕様は Avatar 側の記録だけでは承認できません。
