**これらの JSON を trk-PWA の画面にそのまま入れられるとは、まだ案内していません。** trk-PWA の `tools/import-skin-catalog.mjs` は開発時に目録や 1 枚の JSON を読んで組み込み JS を作る道具です。画面のカスタムスキン JSON の読み込みは別の形式で、1 件ずつ・上限 20 件です（参照版の `js/custom.js`, `js/core.js`）。`skin` を含む `.stpack` もありますが、巻別データの一括インストールとは同じではありません。元の `colors`、多言語名、`type`、`video`、`cli` 等がカスタム形式でそのまま全部再現される保証もありません。

## ご相談したい受け皿

1. **取り込み単位**：利用者が巻の一覧から選び、1 枚または巻単位で追加する場合、既存のカスタム枠とは別のライブラリ枠が適切でしょうか。20 件上限をどう扱うか、すべてを内蔵する案と、利用者が選んだものだけ取り込む案の見積もりをお願いします。自動通信・自動導入は前提にしません。
2. **フォーマットと保存**：まず `{format:"trk-avatar-library-skins", version:1, skins:[…]}` と 1 枚の JSON を候補として、バージョン・サイズ・件数上限・保存先・オフライン復元・旧版の扱いを相談したいです。正本 JSON や既存 `.stpack` の意味は変えず、受け取り形式は双方で合意してから固定します。
3. **重複・削除**：同一 ID の内蔵／導入済み／更新／異なる巻との衝突時に、上書き前の確認、スキップ／更新、利用者の設定を保持した取り消し・削除をどうするか。部分的に失敗したときは、成功・失敗・理由を利用者に見せる案です。
4. **安全・アクセシビリティ**：JSON をデータとして読み、実行可能コードや危険な CSS・パスは受け入れず、既存 sanitizer と合意した上限で検査。色の補正や落とした値は確認できるようにし、キーボード・小画面・実機・オフラインで検証したいです。ライセンスと出典も利用者から辿れるようにしたいです。
5. **Wizard 62 種**：現在の Avatar 目録は 62 種、参照版の trk-PWA の生成物は 24 種です。`--check` は現目録と不一致でした。**38 種を自動で内蔵する決定ではありません**。組み込み／選択式のどちらがよいか、既存 ID・利用者設定・起動順・選択 UI・検査・容量を含め、受け皿の案をお願いします。Avatar 固有の CSS / JS による演出は色データだけでは移りません。
6. **色の課題**：レビューの v3 検査指摘は未解決です。参照版では 62 種中 18 種・23 件の指摘を再現しました。取り込み時の補正と元データ修正をどう分担するか、生成結果と実画面の両方で確認しましょう。未解決のまま「全色 AA 合格」とは扱いません。
