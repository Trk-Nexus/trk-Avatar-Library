**バージョン:** 0.1（草案）  
**作成日:** 2026-11-03  
**対象:** trk!（trk-PWA）再生プレイヤー + trk-Avatar-Library スキンカタログ  
**ライセンス:** GPL-3.0-or-later（本リポジトリと同じ）

---

## 1. 意図・コンセプト

trk! のメディアプレイヤーUI（再生バー・アルバムアート・ボタン群）を介さず、**コンソールライクなCLIインターフェースから直接曲・ファイルを操作する体験**を提供する。

「Wizard（魔導師）」側の視野から設計する。geek/hacker的な「端末を叩く」感覚ではなく、**呪文を唱え、魔導書を開き、ターミナルに呪文を入力する**ような、汎用性を超えた自由度と実験的なUXを誇る。

> 「曲や登録されたファイルを直で叩く」体験は、メディアプレイヤーよりもコンソールを叩く感覚になり、Wizardのようで面白いかもしれない。

スキン側だけでは完結しないため、機能を作った後に導入を再生プレイヤー側に適応する形で開発を行う。本設計書はその第1フェーズ（設計・構想固め）の成果物として、trk-Avatar-Library 側で仕様を策定し、Google Drive で関係者に共有・受け入れを得た後に、スキン制作と本体実装に進む。

## 3. 前提・制約

- **スキン側だけでは完結しない**：CLIパーサー・コマンド実行・再生プレイヤー連携は trk! 本体側で実装が必要。
- **設定の保存**：CLI で変更したスキン・音量・再生位置などは、trk! の設定保存（§6④「設定の保存」）に準拠して保持する。
- **オフライン動作**：ギャラリーHTML（1ファイル・外部参照0）と同様、外部参照ゼロで動作することを目指す。
- **セキュリティ**：ファイルパスを直接受け付ける場合、ディレクトリトラバーサル対策を講じる。
- **通常UIとの共存**：CLI操作だけでなく、従来のメディアプレイヤーUIと並行して利用可能にする。

## 4. CLI コマンド定義（案）

| コマンド | 引数 | 意図・動作 | Wizard 側の表現（例） |
|---|---|---|---|
| `play` | `<track-id>` | 指定トラックを即再生 | `> play 001` |
| `list` | － | 登録ファイル一覧を表示 | `> list` |
| `skin` | `<skin-id>` | スキンを即座に切替 | `> skin wizard-cli` |
| `volume` | `<0-100>` | 音量を直接指定 | `> volume 80` |
| `seek` | `<mm:ss>` | 再生位置を直接指定 | `> seek 1:30` |
| `spell` | `<macro-id>` | 事前登録マクロを実行 | `> spell shuffle-fav` |
| `cast` | `<spell-text>` | 呪文（カスタムコマンド）を実行 | `> cast repeat-all` |
| `grimoire` | － | 魔導書（スキンカタログ）を開く | `> grimoire` |
| `help` | － | コマンド一覧・説明を表示 | `> help` |
| `quit` / `exit` | － | CLIモードを終了 | `> quit` |

### 4.1 マクロ（呪文）登録例
- `shuffle-fav`：お気に入りプレイリストをシャッフル再生
- `repeat-all`：全トラックをループ再生
- `midnight`：暗いスキン + 音量30 + 夜のプレイリスト

## 5. スキン側との連携（trk-Avatar-Library 側で準備すること）

### 5.1 既存スキン
- `wizard-cli`（`cat: ["wizard","dark","access"]`）：黒い端末に白い呪文、コマンドライン魔術。CLI体験のベーススキン。

### 5.2 追加予定スキン（CLI連携強化）
- CLI専用プロンプト表示（`> cast ...` など）
- コンソール風等幅フォント（Courier New / monospace 系）
- 呪文発動エフェクト（光の粒子・轟音ビジュアル）
- 魔導書風・タロット風・ヴォイド風のCLI専用配色

### 5.3 連携方針
- スキンの `cat` に `wizard` を含むものを「CLI対応スキン」として扱う
- `skin <skin-id>` コマンドで即座にスキンを切替、プレイヤーに反映
- スキンの `colors`、`font`、`video` フィールドを CLI 表示に適用

## 7. 検討事項（受け入れ時に確認）

1. **CLIモードのトリガー**：通常UIからどうCLIモードに入るか（設定メニュー？ ショートカット？ コマンドパレット？）
2. **設定保存の整合性**：CLI で変更した値が、通常UIの設定と衝突しないか
3. **ファイルパスの安全性**：`play` 等で直接パスを指定する場合のトラバーサル対策
4. **アクセシビリティ**：コンソール操作だけでなく、マウス/タッチ操作との共存
5. **パフォーマンス**：CLI入力時のレイテンシ、プロンプト表示の応答性
