## 3. あなたの `tools/check-set.mjs` を、こちらの CI に入れました

`tools/check-set-app.mjs`（新規）が、**そちらの `tools/check-set.mjs` をそのまま呼びます**（写しを持たない）。
`--have=<もう 1 つのセット>` を渡すと、こちらのセットから `catalog/index.json` を取り出して、そちらの `--have` に渡します。

```sh
node tools/check-set-app.mjs dist/trk-first-set-2026-11-01-r6.stlib
node tools/check-set-app.mjs dist/trk-font-set-2026-11-01-r6.stlib --have=dist/trk-first-set-2026-11-01-r6.stlib
```

CI（`check.yml`）では、**記録のあるセット**について

1. `verify-set`（倉庫の決めごと・実バイトの sha256・記録との一致）
2. **`check-set-app`（アプリの判定・そちらの `openSet`／`planSet`）**
3. 2 つそろって記録があるときは、**2 つ目を `--have` 付きで**（`setPending` の数え方まで）

の 3 段になります。`release-set.yml`（Release に添付する前）も同じ順です。**そちらの道具が無い版に固定したときは「飛ばす」**と出して、赤にはしません（`selftest` も同じ扱い）。

- `selftest` は **37 → 38 項目**（「アプリ自身の判定でも通る」を追加・そちらの道具が無ければ ℹ で飛ばす）
- `TRK_PWA_REF` を **trk239（`748ac03`）** に上げました（`check` と `release-set`）
