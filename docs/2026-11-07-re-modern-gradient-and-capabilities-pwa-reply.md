# Avatar → PWA：題字の背景と re-modern の今後の方向（2026-11-07）

[題字の背景についてのご相談](https://drive.google.com/file/d/1MiZxrtq2UTMnYMv22DNzIdVRDe-jWo8d/view)をありがとうございます。依頼者と、表現を保つこと、概念を説明できること、今後の作品の自由度について相談しました。以下は Avatar 側の回答と検討の共有です。PWA 側の仕様追加やスケジュールの決定ではありません。

## 題字とグラデーション

**グラデーションを一律に禁止する考えには賛同しません。** 色・光・素材は作品の表現として活かしたいです。一方、グラデーションが文字の背後に重なっている場合、`background-color` だけで計算した対比を実際の対比の保証として扱うことはできません。

確認した [PWA PR #105](https://github.com/Trk-Nexus/trk-PWA/pull/105) の head `b1731aa76b29d579923b0568ffa79286a0a95726` は確認時点で未マージ。`effectiveBg` は祖先の `background-image` に `url(...)` があると適用を控えますが、グラデーションは合成せず背景色で判定します。実画像を扱う 14 OK は PWA 側からの報告であり、今回 Avatar 側が smoke を再実行した結果ではありません。

**単純な計算上の例（実スキン・実ブラウザの画素測定ではありません）**：黒地の `#767676` は背景色だけなら約 4.62:1。そこに白20%が重なる位置は仮定した sRGB 合成で `#333333`、文字との比は約 2.78:1 になります。対象コードを模擬 DOM で呼んだとき、黒を背景とし作品色を通すことを確認しました。「淡い」だけで背景色判定が常に十分とは言えない、という意味で、既存の `.screen` の光が実際に不適切だったと断定するものではありません。

提案は次の三つの経路を実画面で比較することです。**全グラデーションの一律除外を確定する提案ではありません。**

1. 文字背後の合成・色域を十分に把握できる場合は、その範囲で本文と `!` の両方を評価して作品色を使う。
2. 評価しにくい場合でも、装飾を消さずに文字の背後へ対比を確認した面を置くなど、作品の意図に沿う構図を検討する。見え方・既存画面・強制色への影響を実測し、既定・切替は別途合意する。
3. 未知の背景を評価できない場合の安全な代替を検討する。作品色の自動適用を保留して理由を示すことは選択肢ですが、既定色に戻すだけで可読性が保証されたとは言えないため、既存表示と解除も別に確認したいです。

題字の両色は PWA が現在採用する 4.5:1 を目安に、実際に背後へ重なる色を数値で評価してください。端点だけでなく中間色・半透明・複数層、文字位置・折返し、白／暗色、スキン変更後の再判定、画像・動画・未知の背景を検討します。任意 CSS の完全解析や、点のサンプル／一枚の画像だけで全範囲を保証できるとは仮定しません。実際の題字は選曲画面の `.brand h1`。書斎・基地の外枠を将来扱う場合は別の領域として検証します。視認性の目視は有用ですが、4.5:1 の数値を目視だけで判定したとは扱いません。実機・支援技術は引き続き未検証です。

## 作品の「裏面」と開発記録

依頼者は、作品の概念、歴史的文脈、図柄、書体や構図の選択理由・候補、出典を読み物としてたどり、将来的には見本の表情を切り替えて比較できる方向に関心があります。**開発メモは未整理のままでも残し、公開向けの読み物とは分ける**方針を Avatar 側文書に反映しました。公開用には事実・出典・権利・現在の実装状態を確認し、作者の説明と制作側の解釈を区別します。共有フォルダや公開リポジトリにあるメモは、作品ページにリンクしなくても閲覧可能な場合があります。

[カテゴリーのコンセプト](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/main/docs/trk-re-modern-concept.md)、[紹介書式](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/main/docs/trk-re-modern-introduction-template.md)、[ピクセル・コンソールの文章見本](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/main/docs/re-modern-research/05-concept-reverse-pixel-console-draft.md)を参照してください。裏面は体験の呼び名で、回転アニメーションを必須とするものではありません。文章見本や書体・構図の切替は PWA に実装済みではありません。

## 将来の機能の幅と、導入の選択

依頼者は、Avatar Library の作品づくりを PWA の現在のオフライン完結・機能だけに発想を限定せず、メディア再生中心、ユーティリティ、名画・名著等の意匠、自由な構成、大きな素材や機能拡張も責任を持って検討したい意向です。将来的には PWA が作品を紹介・参照し、追加機能を**導入するかは利用者が選ぶ**形も考えられます。

ただし、これは PWA の既定を変更したり、スキンに実行権限を与えたりする依頼ではありません。まず通常のデータ作品と、必要なら別のアドオン・別実行環境を区別し、具体例が出た時点で PWA と受け口を協議したいです。作品を選んだだけで外部通信・サーバー起動・任意コード実行・利用者設定の上書きを行わないことを前提とし、必要な機能ごとの目的、容量、依存、通信先・送信内容、追加権限、オフライン時、停止・解除・復元、出典・権利を事前に分かるようにする案です。

例として、時刻表示はホストが限定して渡す方法、外部 API は通信の個別許可、API キーは作品や URL に埋め込まず漏えい・削除まで検討、ローカルサーバーは OS 上で利用者が明示的に導入・起動・停止する別ヘルパー等を検討できます。通常のブラウザの `index.html` が OS 上に任意の常駐サーバーを直接起動できるとは想定しません。これらはすべて**未実装・未合意の論点**です。ループバック通信も認証・CSRF 等の設計が必要で、「公式」や台帳 ID 一致だけでは配布物や作者の認証になりません。

詳細は[表現の自由と拡張機能の境界](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/main/docs/re-modern-research/06-creative-freedom-and-capabilities.md)を参照してください。PWA 側のオフライン方針や既存環境に追加負担を自動的に課すのではなく、紹介だけに留める・別環境にする選択肢も含めて相談したいです。

## 引き続き守ること・相談

- 共通・書斎・基地は独立選択と現状維持。書斎本文設定、基地の再生・字幕・退出、既存の「スキンのおすすめ」共通ノーツ設定の挙動を維持します。
- ピクセル・コンソールは依頼者が作品として承認済みですが、正式台帳への登録、公開、権利・実機・支援技術・独立レビューの完了は別です。
- 題字のグラデーションについて、現実的に評価可能な範囲や、必要なら文字背後の面を設ける案の影響を一緒に検討できると助かります。現行 PR のマージ・修正判断は PWA 側でお願いします。
- 将来の拡張に関しては、まず「作品紹介の参照」と「追加機能の実行」を分離する受け口の可能性・PWA の制約をお聞かせください。実装や新しいパック形式を今すぐお願いするものではありません。
