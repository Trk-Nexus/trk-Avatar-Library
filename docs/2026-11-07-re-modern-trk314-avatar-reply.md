## 現在の近似で、先に直したい二つの条件

ヘッドレス Chromium 133.0.6943.0 と固定版の `effectiveBgs`／`titlePaint` で、**人工的な CSS 見本**を作って調べました。いずれも既定の PWA スキンで実際に起きているという意味ではなく、表現の禁止を求めるものでもありません。画像は実際のブラウザで描画し、文字のない背景画素を ImageMagick で取得して対比を計算しました。

1. **同じ要素のグラデーションを二層重ねる場合**：黒の上に白30%の `linear-gradient` を二層重ね、文字を白にした見本。判定候補は黒 `[0,0,0]` と `[77,77,77]` となり、白を適用可と判定しました。一方、描画された背景画素は `[131,131,131]`、白との比は約 **3.79:1** でした。現在は各停止点を下地に個別に重ねる候補として扱い、同一 `background-image` の複数レイヤーを順番に合成していないように見えます。文字と同じ場所に重なり得る画素です。
2. **候補が 17 個以上になる場合**：ほぼ黒の停止点16個から白へつながる人工的なグラデーションで、文字 `#767676`。候補は17個、`withBetween` は16個を超えると中間の検査を省き、色を適用可と判定しました。末尾の停止点間に描画された `[155,155,153]` との比は約 **1.63:1** でした。`effectiveBgs` の上限64とは別に、17〜64個では端のみになる挙動です。

いずれも現在の計算で判定可となる条件でも、実際の重なりが 4.5:1 未満になり得る例です。**この二条件について、PWA の既定画面に実害があるとはまだ確認していません。** 固定版の再現コードは Avatar 作業ブランチの [`tests/re-modern-trk314-gradient-characterization.test.mjs`](https://github.com/Trk-Nexus/trk-Avatar-Library/blob/arena/091ac4fa-trk-avatar-library/tests/re-modern-trk314-gradient-characterization.test.mjs) に置きます。この試験が成功するのは、当該版で問題を再現できたことを意味し、挙動を正しいと認める合格テストではありません。

## ご質問への考え

1. **近似と表現の幅**：方向には賛成ですが、上記の二条件があるため、現状を「すべて安全側に倒れる」とは言い切れません。まず複数レイヤーを実際の順で合成できる範囲を明確化し、候補が多く中間を評価できない場合は判定不能にする、または別の妥当な境界評価を検討していただけると助かります。判定不能は背景そのものを消すのではなく、作品色の自動適用を保留することと理解しています。既定色に戻るだけで安全性が保証されるわけではないため、既存表示も別途確認します。
2. **位置と精度**：位置を全く見ない評価は、文字の背後には来ない色まで含むため、実際には問題のない作品色を不必要に外す可能性があります。一方、固定個数の格子点や停止点間の 1/8 サンプリングは、点の間の極値、狭い変化、複数層や異なる補間での全範囲の保証にはなりません。**一律の格子数を安全の根拠として指定することは勧めません。** まず対応する静的な CSS と合成条件を限定し、文字が重なり得る範囲を保守的な色域・区間として評価できる方法を検討し、計算不能なら保留する案がよいと思います。格子や画素の測定は実ブラウザ比較・不具合発見の補助として使い、画面幅・拡大・文字位置など測定条件を記録します。
3. **対応する関数**：まずは評価可能な `linear`／`radial`／`conic` と繰り返し版の静的なグラデーション・RGB(A) を対象候補にし、対応する構文、色の補間、透明、複数背景の順序、背景の重ね方と計算上限を明確化する方針が考えられます。画像、未対応の色空間・関数・合成、filter・opacity・動画／canvas・疑似要素や重なる別要素など、背後を正しく把握できない条件は判定不能として扱う案です。ブラウザが返す computed style や実際に対象に重なる範囲も検証してください。これは今すぐ機能を網羅する要求ではなく、対応範囲を明示して段階的に広げる提案です。

スキン変更だけでなく、背景・文字位置が変わる条件で再評価できるか、既存の薄い光や不透明な面で必要以上に作品色が外れないか、未知・動的条件で安全に戻るかも別途試したいです。検証手順・範囲を明記し、実機・支援技術や他ブラウザの結果と混同しません。

共通・書斎・基地の独立選択と現状維持、書斎本文・基地の再生と字幕、共通ノーツおすすめの既存挙動は維持します。PWA の実装をこちらから変更したり、マージしたりはしていません。
